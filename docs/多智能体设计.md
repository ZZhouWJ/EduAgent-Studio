# EduAgent Studio 多智能体设计

> 实施版本：V2.1
>
> 最近核对：2026-07-17

## 1. 设计概览

系统实现两套相互独立的 AI 编排：

| 编排 | 使用者 | 目标 | 核心实现 |
| --- | --- | --- | --- |
| 学习资源生成图 | 教师 | 针对指定学生、知识点和目标生成可审核资源 | LangGraph `StateGraph` + SQLite checkpoint + SSE |
| Tutor Supervisor | 学生 | 在课程对话中动态选择检索、讲解、练习和多模态工具 | 规则候选集 + LLM tool calling + 意图降级路由 + SSE |

两套编排共享以下基础能力：

- 学生画像、知识点掌握度和课程数据域。
- 课程知识检索与真实 chunk 引用。
- 统一 LLM Gateway、Provider 切换、调用记录和内容安全。
- 对外错误脱敏、执行耗时和可观测轨迹。

## 2. 教师资源生成图

### 2.1 状态输入

`WorkflowState` 保存完整业务上下文：

| 分类 | 字段 |
| --- | --- |
| 业务定位 | `run_id`、`student_id`、`course_id`、`knowledge_point_ids` |
| 生成参数 | `resource_type`、`difficulty`、`generation_goal` |
| 个性化上下文 | `student_profile`、`knowledge_points`、`learning_history` |
| 节点结果 | `diagnosis`、`learning_plan`、`generated_resource`、`assessment`、`teacher_review` |
| 可信与证据 | `evidence_links`、`trustworthiness` |
| 路由控制 | `current_step`、`revision_count`、`quality_score`、`needs_revision` |
| 审计 | `step_history`、`metadata` |

编排入口在读取这些数据前校验教师课程归属、学生与课程关系、知识点归属和请求长度。

### 2.2 节点职责

| 节点 | 输入 | 输出 | 失败处理 |
| --- | --- | --- | --- |
| Diagnosis Agent | 画像、知识点、历史反馈 | 薄弱点、优先级、诊断证据 | 标记 `diagnosis_failed` 并停止后续生成 |
| Planning Agent | 诊断、目标、画像、知识结构 | 学习路径、顺序、时长和资源建议 | 标记 `planning_failed` |
| Resource Generation Agent | 路径、类型、难度、画像、课程证据 | 资源内容、引用、告警和可信等级 | 标记 `generation_failed`，不伪造草稿 |
| Assessment Agent | 资源、画像、学习目标 | 完整性、难度与目标符合度 | 标记 `assessment_failed` |
| Teacher Review Agent | 资源与难度要求 | `quality_score`、风险和审核建议 | 标记审核节点失败 |
| Revision | 资源、审核理由和返工次数 | 修订资源 | 保留上一版和错误记录 |

Teacher Review Agent 仅产生审核建议，不代替教师的人工审核决定。

### 2.3 条件路由

```text
INIT
  → DIAGNOSIS
  → PLANNING
  → GENERATION
  → ASSESSMENT
  → TEACHER_REVIEW
       ├─ quality_score < 7.0 且 revision_count < 3
       │    → REVISION → TEACHER_REVIEW
       └─ 其他
            → COMPLETED
```

任一必要节点进入 `FAILED` 时，Supervisor 直接结束，不将部分结果标记为完整资源。返工上限防止模型在不可满足的审核条件下无限循环。

### 2.4 可用资源类型

| 代码 | 产品类型 |
| --- | --- |
| `lecture` | 课程讲义 |
| `mindmap` | 思维导图 |
| `quiz` | 分层练习题 |
| `code_case` | 代码实操案例 |
| `ppt` | PPT 大纲，可导出可编辑 PPTX |
| `video_script` | 视频/动画脚本 |
| `experiment_report` | 实验报告 |
| `error_analysis` | 错题解析 |
| `learning_card` | 学习卡片 |

后端还保留 `case`、`review` 和 `test` 内容模板，但当前教师工作台不将它们作为默认产品选项。

### 2.5 Checkpoint 和流式事件

- `run_id` 同时是 LangGraph `thread_id`。
- Checkpoint 保存在 `APP_DATA_DIR/agent_workflows.sqlite3`，SQLite 使用 WAL 模式。
- 每个节点在 `step_history` 中记录状态、时间、耗时和错误摘要。
- `POST /api/agents/generate/stream` 返回节点、返工次数、质量分数和结果完成事件。
- `GET /api/agents/workflow/{run_id}` 读取 checkpoint，返回前重新校验请求人对该学生/课程的访问权。

## 3. Tutor Supervisor

### 3.1 编排流程

```text
学生问题
  → 校验学生画像与课程访问
  → 检索课程证据
  → 注入画像 + 知识上下文
  → Tool Registry 按问题预筛选候选能力
  → LLM 选择工具并生成参数
  → 执行工具，结果返回模型
  → 最多 8 步循环
  → 组装最终回答、引用、内容块和执行轨迹
```

如 Provider 不支持 tool calling 或返回不合法工具结构，系统使用已注册的意图路由和安全后备建议，不直接执行未校验的工具名或参数。

### 3.2 工具与子智能体

| ID | 类型 | 能力 |
| --- | --- | --- |
| `retrieve_knowledge` | Tool | 课程材料检索与 chunk 引用 |
| `tts_tool` | Tool | 讯飞语音合成，无凭证时显式不可用 |
| `image_agent` | Tool | 讯飞图像生成，无凭证时不返回假 URL |
| `ppt_agent` | Tool | 生成结构化幻灯片并支持 PPTX 导出 |
| `quiz_agent` | Agent | 按画像、知识点和难度生成自适应练习 |
| `code_case_agent` | Agent | 生成代码案例、运行说明与常见错误 |
| `mindmap_agent` | Agent | 生成 Markdown/Mermaid 思维导图 |
| `planning_agent` | Agent | 根据画像和知识结构规划学习路径 |
| `error_analysis_agent` | Agent | 归类错因，生成正确思路和变式练习 |
| `explanation_skill` | Skill | 用类比或苏格拉底式提问讲解概念 |

Tool Registry 对工具 ID、输入 schema、超时和 handler 进行统一注册。来自模型的参数必须匹配 schema，并由 handler 再次执行业务权限与输入校验。

### 3.3 Tutor SSE 事件

| 事件 | 含义 |
| --- | --- |
| `supervisor.started` | 开始编排并确定候选工具 |
| `supervisor.tool_choice` | 模型选择某工具 |
| `tool.started` / `tool.completed` / `tool.error` | 工具执行进度与结果状态 |
| `agent.started` / `agent.completed` / `agent.error` | 子智能体进度 |
| `supervisor.final` | 最终回答、引用和内容块 |
| `supervisor.max_steps` | 达到 8 步上限后安全结束 |

## 4. LLM Gateway

### 4.1 调用链

```text
Agent/Tool
  → 解析当前模型配置
  → 扫描用户输入与 Prompt
  → Provider 调用
  → 扫描模型正文与 tool arguments
  → 记录状态、耗时、Token 和成本
  → 返回标准化结果
```

当内容安全命中时，Gateway 返回失败，不返回原文、不执行工具，日志只记录风险类别。

### 4.2 Provider 边界

- Mock Provider 用于自动化测试和无外部凭证的本地开发，生产环境强制禁用。
- 讯飞星火、OpenAI-compatible 和 MiniMax 通过独立 Provider 适配。
- 外部凭证缺失或供应商失败时，不用 Mock 结果伪装成真实调用。
- 管理端 API Key 使用 AES-GCM 加密存储，明文不回显。

## 5. 课程证据和防幻觉

Resource Generation Agent 优先按课程和知识点检索已确认文档分块。Prompt 要求引用格式为 `[引用:chunk_id]`，输出后执行：

1. 提取整数 chunk ID。
2. 检查 chunk 是否存在且属于当前课程。
3. 核对知识点关联和确认状态。
4. 将有效关联作为 `evidence_links` 返回。
5. 根据引用覆盖和告警生成 `high` / `medium` / `low` / `draft` 等级。

保存资源时，内容和有效证据链在同一数据库事务中写入。学生只能看到审核通过的资源。

## 6. 可观测性

| 对象 | 记录 |
| --- | --- |
| 工作流 | `run_id`、节点状态、耗时、返工次数、质量分数、错误摘要 |
| LLM 调用 | Provider、Model、状态、Token、耗时、成本和错误类型 |
| Tutor | 工具 ID、参数类型、成功状态、耗时、引用与内容块 |
| 资源 | 可信等级、幻觉告警、证据关联、审核记录 |
| 平台 | 登录、操作、审核、预算和成本统计 |

日志不记录明文 API Key、JWT 密钥或数据库密码，外部异常不向客户端返回堆栈。

## 7. 测试要求

- 节点必须分别测试正常、Provider 失败、不合法 JSON 和无证据分支。
- Supervisor 必须测试工具选择、参数校验、最大步数、工具异常脱敏和回复降级。
- 工作流必须测试返工路由、SSE 最终事件和 SQLite 连接重启后恢复。
- RAG 必须测试中文短语召回、真实 chunk ID、无效引用和证据事务。
- LLM Gateway 必须测试输入/输出/tool arguments 安全拦截、Provider 失败和调用记录。

当前自动化验证基线见 `docs/PROJECT_STATUS.md` 与 `docs/测试说明书.md`。
