## 四、当前最大缺口（按严重程度排序）

### 🔴 严重缺口（阻断核心功能演示）

#### 缺口A：`knowledge_context` 在 Supervisor 中被忽略
- **位置**：`tutor_supervisor.py` 的 `_build_system_prompt()` 方法（第385行）
- **问题**：
  1. `knowledge_context` 参数被 `_build_system_prompt()` 接收，但**仅作为 system prompt 中的占位符文本**（第385行：`ctx = knowledge_context or "（暂无相关知识库内容）"`），没有显式的"知识库上下文"章节
  2. `_call_llm_with_tools()` 也从未将 `knowledge_context` 注入 `messages` 数组
  3. 知识库 chunks 只在 `_build_embed_answer()` 的兜底文本中提到，没有实际内容
- **注意**：非流式路径（`TutorService.chat` → `_generate_answer_multi_agent` → `supervisor.run`）也调用了 `knowledge_context=context`，同样受影响
- **后果**：LLM 回答时看不到知识库原文，引用功能形同虚设；即使模型输出 `[引用:chunk_id]`，也是幻觉
- **修复方向**：
  1. 在 `_build_system_prompt()` 的 system prompt 中新增"## 知识库上下文"章节（第396行附近），显式注入 `knowledge_context` 的完整内容
  2. 在 messages 数组中额外追加一条 `{"role": "system", "content": f"知识库上下文：{knowledge_context}"}` 确保不被 system prompt 截断

#### 缺口B：image_agent / tts_tool / ppt_agent 是 Stub
- **位置**：`tool_registry.py` 第278行（tts_tool）、第286行（image_agent）、第294行（ppt_agent）
- **问题**：三个工具返回空占位数据而非真实内容
- **后果**：学生要求生成图片/音频/PPT 时只能得到 `{"image_url": ""}` 等空数据
- **修复方向**：
  - `image_agent` → 接入 `iflytek_multimodal.py` 的 `generate_image()`
  - `tts_tool` → 接入讯飞 TTS API
  - `ppt_agent` → 实现真实 PPT 生成逻辑

#### 缺口C：嵌入语法依赖模型遵守指令
- **位置**：`tutor_supervisor.py` 第413-431行（system prompt）、`StudentTutor.tsx` 第175行（EMBED_REGEX）
- **问题**：
  1. System prompt 要求 LLM 输出 `:::type:block_id:::` 嵌入语法，但 LLM 不总是遵守
  2. 模型输出纯文本时，内容块只能靠 `unusedBlocks` 兜底渲染在末尾
  3. `EMBED_REGEX` 缺少 `error_analysis` 和 `learning_card` 类型
- **修复方向**：
  1. `_build_embed_answer()` 在 LLM 未主动嵌入时兜底生成
  2. 更新 `EMBED_REGEX` 支持所有 block 类型
  3. 考虑前端主动将 `content_blocks` 注入到 `content` 中而非依赖模型

### 🟡 中等缺口（影响体验完整性）

#### 缺口D：学习路径无前端图谱可视化

- **后果**：LLM 看不到完整代码案例，影响后续回答质量
- **修复方向**：对不同工具类型做差异化摘要长度

## 六、加分项的实际评估

### 智能辅导（赛题加分项17）— **这是学生端核心功能，非加分项**

> ⚠️ 根据赛题原文，多智能体协作是"通过**与学生的智能交互**"触发的，
> 因此智能辅导（学生端 Tutor）是赛题的**核心功能**，不是加分项。

**赛题原文**：
> 当学生在学习过程中遇到问题时，系统提供即时、多模态的答疑解惑服务，通过智能体的数据分析、大模型的知识支持，结合多模态生成技术，为学生提供详细的文字解答、图解说明、短视频讲解等多样化解答形式

**实际现状**：
- ✅ 答疑框架已建立（`tutor_supervisor.py` Tool Calling 循环）
- ✅ 文字解答 + 引用来源 + 执行轨迹已实现
- ✅ 多模态卡片（quiz/code_case/mindmap）渲染已实现
- ✅ GPT/Gemini 风格进度动画（**待实现**，是竞赛演示亮点）
- ❌ **image_agent 是 Stub**（无真实图片生成）
- ❌ **tts_tool 是 Stub**（无语音合成）
- ❌ **ppt_agent 是 Stub**（无真实 PPT 生成）
- ⚠️ **knowledge_context 未注入 LLM**，引用教材原文功能形同虚设
- ⚠️ 嵌入语法无兜底，依赖 LLM 遵守指令

**结论**：答疑框架 80% 完成，进度动画缺失影响演示效果，图片/语音/PPT 生成缺口导致多模态不完整。

### 学习效果评估（赛题加分项18）

**赛题原文**：
> 通过实时跟踪学生的学习行为、练习测试情况、资源使用反馈等数据，依托大模型的数据分析能力实现对学生学习效果的多维度、精准评估；并根据评估结果及时动态调整学习资源推送策略和学习计划

**实际现状**：
- ✅ 反馈提交更新画像（`feedbacks.py` UPSERT）
- ✅ 推荐逻辑存在（`LearningService.recommend_resources()`）
- ⚠️ `assessment_agent.py` 是旧 workflow.py 的一部分，非学生端实时答疑链路的评估
- ⚠️ 评估→调整→学生感知→再次评估 完整闭环未实现
- ⚠️ "推送策略动态调整" 学生端感知不明显

**结论**：反馈和推荐逻辑存在，评估→调整→学生感知完整闭环需要完善。
