## 实施原则

1. 优先做小步可验证的修改，不破坏现有登录、权限、页面、接口
2. 每个任务完成后验证，不跳步
3. 不做无关重构
4. 每次修改后同步更新相关文档

## 任务清单

### T1：数据库初始化数据 — 插入学生画像和掌握度数据

**优先级**：P0（阻断演示）
**涉及文件**：`database/10_insert_a3_initial_data.sql`

**修改内容**：
在 `10_insert_a3_initial_data.sql` 末尾追加：

1. 插入 3 个学生用户（如果 `users` 表没有的话），或确认 user_id 1/2/3 已存在
2. 插入 `student_profiles` 记录（李明/王悦/陈思雨）
3. 插入 `student_knowledge_mastery` 记录（每人 5-8 个知识点的掌握度）
4. 插入 2-3 条 `learning_feedbacks` 示例反馈

**验收标准**：
- `SELECT COUNT(*) FROM student_profiles` 返回 ≥ 3
- `SELECT COUNT(*) FROM student_knowledge_mastery` 返回 ≥ 15
- `/api/profiles` 返回 3 条学生画像
- 智能体工作台学生下拉有内容

### T2：反馈提交触发画像更新闭环

**优先级**：P0（A3 赛题核心要求）
**涉及文件**：`backend/app/routers/feedbacks.py`

**修改内容**：
修改 `submit_feedback`，提交后执行：
1. 计算新的 `self_mastery`（如提交了 quiz_score 则用测验得分，否则用自评）
2. UPDATE `student_knowledge_mastery` 表中该学生对该知识点的掌握度
3. UPDATE `student_profiles.mastery_score` = AVG(all_kp_mastery)
4. 返回更新后的掌握度变化

**验收标准**：
- 提交测验结果后，`student_knowledge_mastery` 表有对应记录
- `student_profiles.mastery_score` 发生变化
