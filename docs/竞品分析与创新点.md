# EduAgent Studio 差异化定位与创新点

> 适用版本：V2.1
>
> 核对日期：2026-07-17
>
> 判定原则：创新点必须能由当前代码、运行数据、测试或真实操作证明；不把规划能力、外部服务宣传或第三方产品推测写成既成事实。

## 1. 产品定位

EduAgent Studio 面向高校专业课程，提供从课程知识、学生状态到资源生产和学习反馈的闭环：

```text
课程材料与知识点
  -> 对话式学生画像
  -> 多智能体诊断、规划、生成、评测与审核建议
  -> 教师人工审核
  -> Tutor、学习路径、任务与已审核资源
  -> 测验和反馈更新掌握度
  -> 推荐、路径与分析重新计算
```

项目不是只完成一次问答或一次内容生成，而是把课程证据、学生画像、教师决策和学习结果保存在同一业务系统中。

## 2. 对比边界

公开 AI 教育产品迭代较快，比赛材料不对具体厂商作未经复核的“有/无”绝对判断。项目采用以下能力类别作为对比背景：

| 产品类别 | 常见核心任务 | EduAgent Studio 重点补充的业务链路 |
| --- | --- | --- |
| 通用对话辅导 | 解释、问答、练习 | 课程证据、学生画像、工具轨迹和效果反馈 |
| 文档问答 | 上传材料、检索、摘要、引用 | 教师确认知识点关联、资源审核和掌握度闭环 |
| 单项内容生成 | PPT、图像、音频或题目生成 | 多资源类型统一编排、质量评测和发布状态机 |
| 教学管理平台 | 课程、任务、成绩和学情管理 | 多智能体资源生产、Tutor 主入口和可追溯 RAG |
| 通用智能体平台 | 工具调用、工作流和自动化 | 高校课程权限、人在回路和学习效果数据模型 |

正式答辩如需出现具体竞品名称，应在提交当天依据其官方资料重新核对，并注明核对日期和来源。

## 3. 可验证创新点

### 3.1 十二维对话式动态学生画像

当前画像覆盖基础信息、知识基础、学习目标、认知风格、资源偏好、学习习惯、学习节奏、互动偏好、表达偏好、动机、可用时间和实践倾向等 12 个可持久化维度，并结合课程知识点掌握度形成学习状态。

实现边界：

- 自然语言输入先抽取为候选字段，不直接覆盖正式画像。
- 学生确认后原子应用，并保存更新前后快照。
- 测验、自评、任务和 Tutor 评估可更新知识点掌握度。
- 前端展示画像维度、掌握度、薄弱点和历史记录。

差异化价值是“对话采集 + 用户确认 + 行为更新”，而不是一次性填写静态问卷。

### 3.2 多智能体资源生产与质量修订

教师工作台使用 LangGraph 编排五类职责：

1. Diagnosis Agent 读取学生画像和掌握度。
2. Planning Agent 确定目标、结构、难度与资源策略。
3. Generation Agent 结合课程证据生成结构化资源。
4. Assessment Agent 评估内容质量和改进项。
5. Teacher Review Agent 给出教师审核建议，但不代替教师发布。

质量分低于阈值时可进入最多 3 次修订循环；执行进度通过 SSE 推送，工作流 checkpoint 持久化在 SQLite 中。最终资源仍需经过 `draft -> pending_review -> approved/rejected` 状态机。

### 3.3 可追溯课程 RAG 与防幻觉边界

当前课程检索基于 MySQL 中的真实课程分块，使用 BM25 与中文 2 至 4 字 n-gram 召回，不依赖 PostgreSQL 或 pgvector。

每次资源生成可形成：

- 整数 `chunk_id` 引用。
- 引用对应的课程、章节、原文和知识点关联。
- 引用覆盖率、可信等级和风险提示。
- 缺少有效引用时的草稿降级。
- 教师复核后的人工发布边界。

这使“模型回答正确”从不可验证判断，转化为可打开、可核对、可审核的证据链。

### 3.4 对话主入口与专业工作台并存

学生以 Tutor 作为高频主入口，同时保留画像、路径、任务、资源和分析页面。Tutor Supervisor 可根据意图调用课程检索、讲解、练习、代码、思维导图、PPT、图像和语音等工具，并向前端返回文本、执行状态和结构化内容块。

教师和管理员保留专业工作台，用于课程知识库、资源生成审核、模型配置、成本、安全和审计。该结构兼顾低门槛交互与可管理的专业流程。

### 3.5 学习结果驱动的动态路径与推荐

学习路径不是预生成图片或固定清单，而是根据课程知识层级、前置关系和当前掌握度实时构建。学习反馈会触发：

```text
反馈或测验
  -> 更新目标知识点掌握度
  -> 重算综合掌握度与薄弱点
  -> 重新生成当前路径
  -> 调整已审核资源推荐顺序
  -> 更新教师和学生分析视图
```

学生资源接口只返回已审核内容，并按知识点归属、难度适配和学习历史排序，避免将未审核生成结果直接推送给学生。

### 3.6 模型治理、内容安全与审计统一落地

LLM Gateway 统一处理模型路由、调用记录、Token、耗时和成本。输入、输出和工具参数均经过内容安全检查，管理员可配置小时调用上限、月度预算和治理策略。

API Key 加密入库且不通过接口回显明文。操作日志、登录日志和模型调用日志为比赛演示和后续运维提供可核对记录。

## 4. A3 赛题价值矩阵

| 赛题关注点 | 当前实现 | 可演示证据 |
| --- | --- | --- |
| 具体高校课程 | CS301《数据库系统原理》9 章知识材料 | 课程知识库与 9/9 知识点召回 |
| 不少于 6 维画像 | 12 个可持久化维度 + 掌握度 | 对话抽取、确认卡片、历史快照 |
| 多智能体协同 | 五智能体资源流水线 + Tutor Supervisor | SSE 节点轨迹、工具执行轨迹 |
| 至少 5 种资源 | 工作台 9 种显式类型，后端 12 种结构类型 | 生成结果和结构化内容块 |
| 个性化路径 | 实时知识点路径与预计时长 | 路径图、薄弱点和前置关系 |
| 画像驱动推荐 | 已审核资源按画像和历史排序 | 学生资源页、推荐理由 |
| 流式交互 | 工作台 SSE、Tutor 流式文本和工具状态 | 生成过程页面 |
| 防幻觉 | 检索、引用校验、降级和教师审核 | chunk 原文、可信等级、审核记录 |
| 内容安全 | 输入、输出、工具参数三处检查 | 管理端策略和调用日志 |
| 学习效果闭环 | 反馈更新掌握度、路径、推荐和分析 | 更新前后数据对比 |

## 6. 宣传口径约束

对外材料仅使用以下表述：

- “已实现”必须能在当前 `main` 分支和运行环境复现。
- “已接入讯飞”仅在真实凭证联调成功后使用，并展示调用审计。
- 图像、语音等能力若走降级实现，应明确说明，不包装成外部模型成功调用。
- 不宣称使用当前运行链路中不存在的 PostgreSQL、pgvector、MinIO 或 Vue 前端。
- 不宣称 Teacher Review Agent 自动批准资源，最终发布决定属于教师。
