# 00_AI开发总控规范

文档版本：v1.0  
适用项目：智研协作：面向高校项目协作的 AI 任务生成与质量审计管理系统  
适用对象：Cursor、Codex、Claude Code、ChatGPT、DeepSeek、通义灵码等 AI 编程助手  
使用方式：每次让 AI 写代码前，必须同时提供本文件、当前阶段任务卡、数据库 Schema 冻结说明。

---

## 0. 文档目的

本文档用于约束 AI 编程助手在本项目开发中的行为边界、技术栈、数据库结构、代码风格、任务执行方式和验收标准。AI 编程助手不得将本文档理解为创意发挥空间，而应将其视为强约束开发规约。

本项目目标是完成一个完整、可运行、数据库设计扎实、界面友好、功能闭环清晰的信息管理系统。开发过程必须优先满足数据库课程要求，包括：关系型数据库设计、主外键约束、嵌入式 SQL、事务一致性、多角色权限、图形化交互界面、系统测试和运行维护说明。

## 1. 项目一句话目标

本项目不是普通大模型聊天平台，也不是 API 转发平台，而是：

> 面向高校课程项目、科研训练和竞赛项目的人机协同内容管理系统，通过项目空间、任务版本、AI 辅助生成、人工修改、质量审核、成果归档和调用审计，实现 AI 使用过程的可管理、可追踪、可审核和可维护。

AI 生成内容不能直接作为最终成果，必须经过人工修改、负责人审核或教师确认后才能进入成果库。

## 2. 固定技术栈

```text
前端：Vue3 + Vite + Element Plus + Pinia + Vue Router + ECharts
后端：Python FastAPI
数据库：MySQL 8.0 优先；可适配 SQL Server
数据库访问：参数化 SQL / Repository 层
模型调用：Mock ModelAdapter + 可选真实模型 API
代码管理：Git
```

除非用户明确要求，否则不得替换。

## 3. 禁止 AI 自行发挥的内容

AI 编程助手必须遵守以下禁止事项：

1. 禁止自行更换技术栈；
2. 禁止将 Vue3 改为 React、Next.js、Svelte；
3. 禁止将 FastAPI 改为 Flask、Django、Spring Boot；
4. 禁止将 MySQL / SQL Server 改为 MongoDB、SQLite、PostgreSQL；
5. 禁止自行删除软删除字段；
6. 禁止自行删除操作日志、登录日志、调用日志；
7. 禁止自行合并数据库表；
8. 禁止自行发明核心业务表；
9. 禁止自行重命名字段；
10. 禁止把系统做成普通聊天机器人；
11. 禁止把系统做成 API Key 分发或转卖平台；
12. 禁止引入未经确认的大型依赖；
13. 禁止一次性生成全项目代码；
14. 禁止不解释原因直接重构已有代码；
15. 禁止绕过嵌入式 SQL 要求；
16. 禁止完全依赖 ORM 替代 SQL；
17. 禁止用伪代码冒充可运行代码；
18. 禁止在日志、前端、测试数据中暴露明文 API Key；
19. 禁止删除审计类数据；
20. 禁止跳过测试说明。

## 5. 数据库开发强约束

### 5.1 Schema 是唯一事实来源

数据库结构以 `docs/01_数据库Schema冻结说明.md` 和 `database/02_create_tables.sql` 为唯一事实来源。如果某个字段不存在，AI 不得自行创造字段名。必须先说明：

```text
当前文档中未找到该字段，建议补充字段如下，请确认后再实现。
```

### 5.2 所有核心业务表必须支持软删除

核心业务表必须包含：`is_deleted`、`deleted_at`、`deleted_by`、`created_at`、`created_by`、`updated_at`、`updated_by`。普通查询必须默认加：

```sql
WHERE is_deleted = 0
```

审计表如 `operation_logs`、`login_logs`、`ai_invocations` 原则上不做普通删除。如确需清理，只能做归档，不做业务物理删除。

### 5.3 必须使用参数化 SQL

禁止字符串拼接 SQL。

错误示例：

```python
sql = f"SELECT * FROM users WHERE username = '{username}'"
```

正确示例：

```python
sql = "SELECT * FROM users WHERE username = %s AND is_deleted = 0"
cursor.execute(sql, (username,))
```

### 5.4 关键操作必须使用事务

以下业务必须使用事务：AI 任务生成、输出提交审核、审核通过并采用、审核退回、项目一键归档、分支合并、软删除项目或任务、修改用户角色权限、API Key 配置更新、人工编辑生成新版本。

### 5.5 不允许用 ORM 替代核心 SQL

可以封装 Repository 层，但核心数据库操作必须体现嵌入式 SQL。课程要求强调通过嵌入式 SQL 完成核心数据管理功能，所以不能完全依赖 ORM。

## 6. 系统核心业务流程不得改变

本系统必须围绕以下主流程开发：

```text
创建项目空间 → 添加项目成员 → 创建项目任务 → 创建任务分支 → 选择提示词模板 → 调用模型或人工撰写 → 保存输出版本 → 人工修改 → 提交审核 → 负责人/教师审核 → 通过后进入成果库 → 记录日志和统计数据
```

不得简化成：

```text
用户输入问题 → AI 返回回答
```

## 7. 输出版本与乐观锁规则

所有 AI 生成、人工编辑、人工合并内容都必须进入 `task_outputs` 表。`task_outputs.source_type` 只允许使用：`ai_generated`、`manual_edit`、`hybrid`、`manual_merge`。

每个版本必须保存：`parent_output_id`、`source_type`、`lock_version`、`last_modified_at`、`last_modified_by`、`edit_summary`。多人编辑时必须使用乐观锁：

```sql
UPDATE task_outputs
SET content = ?, lock_version = lock_version + 1, last_modified_at = NOW(), last_modified_by = ?, edit_summary = ?
WHERE output_id = ? AND lock_version = ?;
```

如果影响行数为 0，必须提示用户刷新或另存为新版本。

## 8. 权限控制规则

系统至少包含四类角色：`student_member`、`project_leader`、`teacher`、`admin`。

权限原则：学生只能查看自己参与的项目；项目负责人可以审核本项目内容；指导教师可以查看指导项目并添加意见；管理员可以管理用户、角色、模型、模板和日志；普通成员不能管理模型 API Key；普通成员不能查看完整 API Key；普通成员不能删除审计日志；只有负责人、教师、管理员可以采用成果。

## 9. API Key 安全规则

API Key 不得明文存储。必须采用 AES-256-GCM 加密。数据库中只允许保存：`encrypted_api_key`、`key_iv`、`key_tag`、`key_version`、`key_mask`。前端只能展示脱敏值，例如 `sk-****abcd`。日志中禁止出现完整 API Key。加密主密钥不允许写入代码仓库，必须来自环境变量、服务器配置文件或密钥管理服务。

## 10. 前端开发规则

前端必须使用 Vue3。页面优先实现：登录页、首页仪表盘、项目列表页、项目详情页、任务创建页、任务详情页、AI 生成与人工编辑页、版本时间线页、审核中心页、成果库页、模型管理页、提示词模板页、调用日志页、用户管理页。

课程设计版允许降级：流式输出可以降级为整段返回后渲染；打字机效果可以不做；代码高亮可先用普通代码块；Diff 对比可先用版本时间线和修改说明代替。

## 11. 后端开发规则

后端必须使用 FastAPI。每个模块分三层：router 处理接口请求，service 处理业务逻辑，repository 执行参数化 SQL。禁止把 SQL、业务逻辑、接口返回全部写在一个文件里。

## 12. 模型调用规则

课程设计阶段不要求接入大量真实模型。建议实现 1 个真实模型 API + 2 到 3 个 Mock 模型。Mock 模型必须模拟不同输出风格，例如 Mock-Writer、Mock-Code、Mock-Reviewer。

## 13. 统一接口返回格式

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

错误示例：

```json
{
  "code": 4001,
  "message": "权限不足",
  "data": null
}
```

## 14. 统一状态字段

| 字段 | 允许值 | 说明 |
| --- | --- | --- |
| users.status | active / disabled | 用户正常 / 禁用 |
| projects.status | active / archived / suspended | 项目进行中 / 已归档 / 暂停 |
| project_tasks.status | draft / running / generated / submitted / approved / rejected / revision_required / adopted / archived / conflict_pending | 任务全流程状态 |
| task_branches.status | active / merged / closed / conflict_pending | 分支状态 |
| review_requests.request_status | pending / approved / rejected / revision_required | 审核请求状态 |
| task_outputs.source_type | ai_generated / manual_edit / hybrid / manual_merge | 内容来源 |
| ai_invocations.status | success / failed / timeout / blocked | 模型调用状态 |


不得自行发明其他状态。

## 15. 任务执行方式

AI 编程助手每次只能执行一个明确任务。每次任务必须按以下格式输出：本次修改范围、涉及文件、实现思路、完整代码、数据库影响、运行步骤、测试步骤、验收清单、风险与回滚方式。

如果任务涉及数据库，必须额外输出：涉及哪些表、是否需要新增字段、是否影响外键、是否需要事务、是否需要更新初始化数据。

## 16. 开发优先级

```text
第 1 阶段：数据库脚本
第 2 阶段：后端基础框架
第 3 阶段：用户登录与权限
第 4 阶段：项目空间管理
第 5 阶段：任务与版本管理
第 6 阶段：提示词模板管理
第 7 阶段：模型调用与调用日志
第 8 阶段：人工编辑与乐观锁
第 9 阶段：审核中心
第 10 阶段：成果库
第 11 阶段：统计看板
第 12 阶段：系统测试与报告截图
```

不得一开始就写 UI 美化、动画、复杂聊天功能。

## 17. 不确定时的处理方式

如果 AI 遇到不确定问题，必须停止编造，并按以下格式提出：

```text
我无法从当前文档确认以下问题：
1. ...
2. ...

我建议的默认方案是：
1. ...

请确认后我再继续实现。
```

## 18. 最终原则

本项目开发以“可运行、可测试、可维护、可解释、可写入课程报告”为第一原则。美观度不能优先于数据库正确性、业务闭环、权限与安全、事务一致性、测试可复现、报告可截图证明。
