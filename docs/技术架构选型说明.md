# EduAgent Studio 技术架构选型说明

> 本文档解释当前实施技术的选择理由。组件拓扑和运行边界见 `docs/ARCHITECTURE.md`。
>
> 最近核对：2026-07-17

## 1. 选型原则

1. **以赛题闭环为中心**：技术必须支撑对话画像、多智能体、课程知识、审核发布和学习反馈，不为展示堆叠不使用的中间件。
2. **真实可运行**：开发、测试和 Docker Compose 使用同一核心数据模型。
3. **可追溯和可治理**：模型调用、课程证据、教师审核、成本和操作都有结构化记录。
4. **先控制复杂度**：在数据规模未达到瓶颈前，优先使用可验证、可部署的组件，而不是引入第二套数据库。
5. **外部能力可替换**：模型和多模态供应商通过 Gateway/Service 适配，不渗透到页面和业务 Repository。

## 2. 前端

| 技术 | 当前用途 | 选择理由 |
| --- | --- | --- |
| React 18 + TypeScript | 三角色 SPA、组件与业务类型 | 组件生态完整，类型检查能在构建前阻止 API 契约偏差 |
| Vite 6 | 开发服务与产物构建 | 启动和增量编译快，生产产物可由 Nginx 静态托管 |
| React Router 6 | 懒加载路由和角色导航 | 与 React 页面结构一致，支持路由级错误边界 |
| Zustand | 认证与用户状态 | API 简单，避免为少量全局状态引入较重模型 |
| Tailwind CSS 4 | 设计 Token、响应式密度与状态样式 | 可快速建立一致间距、色彩和布局约束 |
| Radix UI | Dialog、Select、Tabs 等复合控件 | 提供键盘和 ARIA 基础，项目在其上实现视觉一致性 |
| Recharts + ECharts | 学情、成本、掌握度和分布图 | Recharts 适合 React 组件图表，ECharts 适合复杂交互可视化 |
| DOMPurify + Markdown | AI 回答和学习资源渲染 | 先解析再消毒，防止模型/用户内容注入可执行 HTML |

### 未选用方案

- **Vue 3 / Element Plus**：是早期原型技术，当前代码已完成 React 迁移，不维护双前端。
- **Next.js**：产品为登录后业务工作台，当前不依赖 SSR/SEO，SPA + Nginx 更简洁。
- **Redux**：当前全局状态范围小，Zustand 已能满足。如后续出现大量跨页协作状态，再评估更强约束的方案。

## 3. API 与业务层

| 技术 | 当前用途 | 选择理由 |
| --- | --- | --- |
| FastAPI | REST、SSE、依赖注入和 OpenAPI | Python AI 生态友好，异步接口和 Pydantic 请求校验成熟 |
| Pydantic 2 | 配置和 API 模型 | 统一输入边界，为生产配置提供强制安全校验 |
| PyMySQL | 参数化 SQL 与事务 | 当前数据模型以 SQL 脚本和存储过程为基础，直接 SQL 便于审查和精确控制事务 |
| JWT + `auth_sessions` | 无状态请求认证与可撤销会话 | 保留 JWT 跨服务便利，同时支持登出立即失效 |
| SSE | 智能体节点与 Tutor 工具进度 | 当前主要是服务器到客户端的单向事件，比全双工 WebSocket 更简单、易经过反向代理 |

项目使用 Router → Service → Repository 分层。这个边界使权限、事务和模型调用可以独立测试，避免在 HTTP 处理器中混合 SQL 和 AI 编排。

## 4. 多智能体与模型

| 技术 | 当前用途 | 选择理由 |
| --- | --- | --- |
| LangGraph | 诊断、规划、生成、评测、审核与返工状态图 | 条件路由、循环、checkpoint 和逐节点输出适合可审计智能体流程 |
| LangChain Core | 消息、工具和模型交互基础类型 | 与 LangGraph 直接兼容，不引入不需要的高层 Agent 黑盒 |
| SQLite Checkpoint | LangGraph 运行状态持久化 | 资源生成规模下实现简单，依赖少，可在进程重启后恢复 |
| 统一 LLM Gateway | Provider 选择、调用记录、内容安全与错误降级 | 业务 Agent 不绑定讯飞或单一兼容接口 |
| Tutor Supervisor | 课程对话中的工具选择与多轮调用 | 规则候选集降低无关工具暴露，模型 tool calling 与降级路由同时保证灵活性和可用性 |

### Checkpoint 扩展条件

SQLite 适合当前单 Backend 副本和竞赛部署。当出现以下任一情况时，再迁移到支持多副本共享的 checkpoint store：

- Backend 水平扩容为多个实例；
- 并发工作流持续造成 SQLite 写锁竞争；
- 需要跨节点容灾与集中备份。

迁移时只替换 LangGraph checkpointer，不改变业务 MySQL 表。

## 5. 数据与检索

| 技术 | 当前用途 | 选择理由 |
| --- | --- | --- |
| MySQL 8.4 | 所有业务、课程知识、画像、审核与审计数据 | 已有完整 schema、迁移、事务和测试基线，使用单一业务数据库降低一致性成本 |
| BM25 + 中文 n-gram | 课程文档分块检索 | 对当前单课程知识库可解释、可离线、可测试，已覆盖 9/9 课程知识点 |
| Redis 7.4 | 缓存与 Celery broker/result | 成熟稳定，同时有独立健康检查 |
| 持久数据目录 | 上传材料、导出文件与 checkpoint | Docker 卷已满足当前单节点部署，无需引入未使用的对象存储 |

### 为什么当前不用 PostgreSQL + pgvector

早期方案准备了 PostgreSQL/pgvector 脚本，但当前运行链路没有使用它们。保留 MySQL + 轻量检索的原因是：

1. 当前知识库规模小，中文关键词与知识点绑定已提供稳定召回。
2. 资源证据要求可解释的真实 chunk ID，当前方案可直接审核。
3. 引入第二数据库会增加初始化、备份、网络和一致性复杂度，但尚无实测性能需求。

当课程文档扩展到大规模、出现跨课程语义问答或 BM25 离线评估明显低于目标时，再以检索评测集对比 embedding/混合检索，而不是直接替换业务数据库。

## 6. 异步任务与部署

| 技术 | 用途 | 选择理由 |
| --- | --- | --- |
| Celery Worker | 可后台执行的文档/检索任务 | 与 Python 服务共享代码和配置 |
| Celery Beat | 周期调度 | 将周期任务与 Web 进程分离 |
| Docker Compose | 竞赛/单节点完整运行栈 | 一份 `.env` 可复现服务依赖、健康检查和持久卷 |
| Nginx | SPA 静态托管与 API 反代 | 容器简洁，支持 SPA fallback 和健康端点 |

Docker Compose 并不代替生产安全配置。对外部署时仍需 HTTPS、受限网络、密钥管理、数据备份和恢复演练。

## 7. 安全选型

| 风险 | 实施措施 |
| --- | --- |
| 密码泄露 | BCrypt 哈希，不保存明文 |
| 模型密钥泄露 | AES-GCM 加密入库，API 只返回配置状态 |
| Token 无法撤销 | JWT 结合 `auth_sessions` 服务端会话 |
| XSS | React 默认转义 + Markdown 消毒 + 不信任 HTML 输入 |
| SQL 注入 | Repository 参数化 SQL，动态 `IN` 只生成占位符数量 |
| 越权访问 | 后端 RBAC + 课程所有权 + 资源/会话所有权 |
| Prompt/tool 攻击 | LLM 输入、输出和 tool arguments 内容安全扫描 |
| AI 幻觉 | 课程证据检索、引用 ID 校验、可信等级和教师发布审核 |

## 8. 质量工具链

- Python `unittest` 覆盖 Service、Repository 调用、权限、智能体、RAG、安全和迁移清单。
- TypeScript `tsc --noEmit` 作为前端 lint/契约门禁，Vite 构建验证产物。
- `npm audit --omit=dev` 审计前端生产依赖，`pip check` 检查 Python 依赖一致性。
- 浏览器自动化复核三角色路由、390px/1440px 视口、无名控件和控制台错误。
- API、MySQL、Redis 和 Web 有独立健康检查。

## 9. 选型复核规则

引入新基础组件前必须回答：

1. 它解决了哪个可量化的当前瓶颈？
2. 现有组件为什么无法通过局部改造解决？
3. 它增加了哪些部署、备份、安全和观测负担？
4. 是否有评估数据、回滚路径和运行手册？
5. 是否同步更新 Compose、配置校验、健康检查、测试和文档？

只有在收益可证明且运行责任完整时，新组件才进入实施架构。
