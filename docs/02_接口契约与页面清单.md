# 02_接口契约与页面清单

文档版本：v1.0  
适用项目：智研协作系统  
用途：约束后端接口、前端页面、权限边界和数据返回格式，防止 AI 开发时自行发明接口或页面。

---

## 0. 总原则

1. 接口契约是前后端联调的唯一依据。
2. AI 不得随意更改接口路径。
3. AI 不得随意改变统一返回格式。
4. AI 不得跳过权限校验。
5. AI 不得在接口中返回明文 API Key。
6. AI 不得新增页面前先新增接口，必须遵循本文件。
7. 如接口不够用，必须提出接口变更申请。

## 1. 统一接口规范

Base URL：`/api`

成功返回：

```json
{"code": 0, "message": "success", "data": {}}
```

失败返回：

```json
{"code": 4001, "message": "权限不足", "data": null}
```

分页返回：

```json
{"code":0,"message":"success","data":{"items":[],"total":0,"page":1,"page_size":10}}
```

错误码：0 成功；4000 参数错误；4001 权限不足；4002 未登录；4003 资源不存在；4004 数据冲突/乐观锁失败；4005 状态不允许操作；5000 系统错误；5001 模型调用失败；5002 数据库事务失败。

## 3. 关键接口契约

### 3.1 登录

```http
POST /api/auth/login
```

请求：

```json
{"username":"admin","password":"123456"}
```

返回：

```json
{"code":0,"message":"success","data":{"token":"jwt-token","user":{"user_id":1,"username":"admin","real_name":"系统管理员","roles":["admin"]}}}
```

### 3.2 创建项目

```http
POST /api/projects
```

请求：

```json
{"project_name":"数据库课程设计项目","project_type":"course_project","description":"数据库管理实务结课设计"}
```

要求：创建项目后自动将创建人写入 `project_members`，并写入 `operation_logs`。

### 3.3 创建任务

```http
POST /api/projects/{project_id}/tasks
```

请求：

```json
{"task_type_id":1,"title":"生成需求分析初稿","description":"为数据库课程报告生成需求分析部分","assignee_id":2,"priority":"normal","due_date":"2026-06-10 23:59:59"}
```

### 3.4 执行模型生成

```http
POST /api/tasks/{task_id}/generate
```

请求：

```json
{"branch_id":1,"model_ids":[1,2],"prompt_version_id":1,"input_text":"请生成数据库课程报告需求分析部分"}
```

要求：必须写入 `ai_invocations`、成功时写入 `task_outputs`、写入 `cost_records`、写入 `operation_logs`，并使用事务。

### 3.5 编辑输出版本

```http
PUT /api/outputs/{output_id}
```

请求必须带 `lock_version`：

```json
{"content":"新的内容","lock_version":3,"edit_summary":"修改格式并补充说明"}
```

乐观锁失败返回：

```json
{"code":4004,"message":"当前内容已被其他成员修改，请刷新后重新编辑，或另存为新版本。","data":null}
```

### 3.6 提交审核

```http
POST /api/outputs/{output_id}/submit-review
```

请求：

```json
{"reviewer_id":3,"submit_note":"请审核需求分析部分是否可进入最终报告"}
```

### 3.7 完成审核

```http
POST /api/reviews/{request_id}/complete
```

请求：

```json
{"review_status":"approved","accuracy_score":9,"completeness_score":8.5,"logic_score":9,"format_score":8,"usability_score":9,"risk_score":1,"review_comment":"整体可用，建议补充非功能需求。","issue_tag_ids":[1,3]}
```

要求：写入 `output_reviews`，更新审核请求、输出版本、任务状态，写入问题标签关联和操作日志，使用事务。

### 3.8 采用成果

```http
POST /api/outputs/{output_id}/adopt
```

请求：

```json
{"artifact_title":"需求分析最终版","artifact_type":"需求分析","release_version":"v1.0"}
```

权限：项目负责人、指导教师、管理员。

### 3.9 分支合并

```http
POST /api/tasks/{task_id}/merge
```

请求：

```json
{"base_output_id":1,"source_output_id":2,"target_output_id":3,"merge_strategy":"manual_merge","merged_content":"负责人手动合并后的内容","merge_comment":"综合 A 版本结构和 B 版本细节。"}
```

要求：不允许直接覆盖；手动合并必须生成新的 `task_outputs`；写入 `merge_records` 和 `operation_logs`；使用事务。

## 6. 接口变更申请格式

如需新增或修改接口，AI 必须先输出：

```text
接口变更申请

1. 接口路径：
2. 请求方法：
3. 变更类型：新增 / 修改 / 删除
4. 变更原因：
5. 涉及页面：
6. 涉及数据库表：
7. 是否需要事务：
8. 请求参数：
9. 返回结构：
10. 请确认后我再实现。
```
