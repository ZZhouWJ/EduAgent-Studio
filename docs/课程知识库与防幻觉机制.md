# EduAgent Studio 课程知识库与防幻觉机制

> 实施版本：V2.1
>
> 最近核对：2026-07-17

## 1. 目标与边界

课程知识库为多智能体资源生成和 Tutor 问答提供可追溯证据。它的目标不是声称“模型不再幻觉”，而是把风险转换为可检查的工程控制：

1. 生成前优先提供教师管理的课程原文。
2. 生成后校验引用的 chunk ID 是否真实存在。
3. 将资源与引用原文持久化关联。
4. 没有证据或引用异常时降低可信等级。
5. 学生只看到教师审核通过的资源。

当前检索运行在 MySQL 中的课程分块上，使用 BM25 与中文 n-gram。`embedding_vector_id` 是数据模型预留字段，PostgreSQL/pgvector 不是当前运行依赖。

## 2. 系统流程

```text
教师上传课程材料
  → 文件边界和真实格式校验
  → APP_DATA_DIR/materials 持久化 + course_materials 记录
  → 解析 PDF/DOCX/PPTX/Markdown/TXT
  → 分块、来源位置、检索词和 SHA-256 哈希
  → course_material_chunks
  → 按 BM25 生成知识点候选关联
  → 教师确认/拒绝 kp_chunk_links
  → Agent/Tutor 检索课程证据
  → 生成内容中标记 [引用:chunk_id]
  → 输出后引用一致性校验
  → 保存资源 + resource_evidence_links
  → 教师核验证据并审核资源
```

## 3. 数据模型

### 3.1 课程材料

| 表 | 关键字段 | 作用 |
| --- | --- | --- |
| `course_materials` | `course_id`、`filename`、`file_type`、`storage_path`、`status`、`material_version`、`total_chars` | 材料元数据、解析状态和版本 |
| `course_material_chunks` | `chunk_id`、`material_id`、`course_id`、`title`、`content`、`source_page`、`source_paragraph`、`bm25_terms`、`chunk_hash`、`material_version` | 可检索原文分块和来源位置 |

材料状态：

```text
pending → parsing → parsed
                  └─ failed（首次解析无可用版本）
```

对已解析材料重新解析时，旧 chunk 在新版本成功写入前保持可用。重新解析失败会恢复 `parsed` 并保留上一版，不用空结果覆盖知识库。

### 3.2 证据关联

| 表 | 状态 | 作用 |
| --- | --- | --- |
| `kp_chunk_links` | `pending` / `confirmed` / `rejected` | 知识点与课程 chunk 的多对多匹配 |
| `resource_evidence_links` | `pending` / `verified` / `rejected` / `replaced` | 学习资源与引用 chunk 的追溯关系 |

`kp_chunk_links` 记录匹配方法、相关度、匹配版本、验证人和验证时间。资源证据记录原文摘要、使用方式、页码/段落与审核状态。

材料重新解析成功时，一个数据库事务会：

1. 将引用旧 chunk 的资源证据标记为 `replaced`。
2. 删除旧 chunk 的知识点匹配。
3. 软删除旧 chunk。
4. 插入新 chunk，更新材料版本和统计。

任一步失败时整体回滚。

## 4. 上传安全与解析

### 4.1 上传边界

| 检查 | 实施 |
| --- | --- |
| 容量 | 最大 20 MiB，Router 只读取上限 + 1 字节，防止无界内存分配 |
| 文件名 | 去除路径片段，只保留安全基名 |
| PDF | 检查 `%PDF-` 文件头 |
| DOCX/PPTX | 检查 ZIP 容器及 `word/document.xml` / `ppt/presentation.xml` |
| Markdown/TXT | 拒绝 NUL 字节，要求 UTF-8 |
| 存储名 | 使用 UUID 文件名，不直接使用用户输入作为路径 |
| 失败清理 | 数据库记录创建失败时删除已写入的文件 |

文件存放在 `APP_DATA_DIR/materials`，Compose 中位于 `backend_data` 持久卷。下载和详情查看前必须验证课程数据域。

### 4.2 解析策略

| 格式 | 解析方式 | 来源位置 |
| --- | --- | --- |
| PDF | `pypdf` 按页提取文本，每页再按段落分块 | `source_page` |
| DOCX | `python-docx` 读取段落、标题层级和表格 | 标题/段落序号 |
| PPTX | `python-pptx` 读取幻灯片标题、文本框和表格 | 幻灯片序号 |
| Markdown | 按标题章节分割，超长章节再按段落分块 | 章节/段落 |
| TXT | 按空行分段并合并过短内容 | 段落序号 |

默认 chunk 目标上限为约 2000 个字符。每个 chunk 写入标题、内容、页码/段落、检索词、顺序、材料版本和内容 SHA-256。

当前 PDF 解析依赖文档中存在可提取文本层。纯扫描 PDF 的 OCR 不属于当前本地解析链路，如无有效文本会显式返回“未能提取有效内容”。

## 5. 检索算法

### 5.1 候选集

检索首先使用 `course_id` 在 SQL 层限制课程，可选使用 `kp_id` 进一步限定知识点。只读取 `is_deleted = 0` 的 chunk，不在内存中混合其他课程数据。

### 5.2 统一分词

教师搜索 API 和 Agent RAG 共用 `tokenize_for_search()`：

- 中文连续片段生成 2、3、4 字 n-gram。
- 英文和数字转小写并按词元保留。
- 过滤高频单字停用词。

这使“事务与 ACID”和“事务与并发控制中的 ACID 特性”共享“事务”、`acid` 等词元，不依赖外部中文分词服务。

### 5.3 BM25 评分

对每个候选 chunk，系统将标题、`bm25_terms` 和正文组合成检索文本，使用：

- `k1 = 1.5`
- `b = 0.75`
- 词频饱和、文档长度归一化和 IDF

只返回得分大于 0 的 Top-K 结果，API `limit` 范围为 1–20，查询长度上限为 2000 字符。

Agent 检索优先读取 `confirmed` 知识点关联；某个知识点无已确认关联时，使用该知识点名称执行 BM25 兜底检索。数据库完全为空时有内置小型课程材料作开发降级，但静态字符串 ID 不会被伪写为数据库证据关联。

## 6. 知识点匹配与教师确认

解析完成后，系统使用 chunk 检索词与课程知识点计算候选匹配，写入 `kp_chunk_links` 时默认为 `pending`。

教师或管理员可以：

- 按课程查看待确认关联。
- 将候选标记为 `confirmed` 或 `rejected`。
- 查看匹配方法、相关度和原文位置。

教师不能查看或验证其他教师课程的关联；未指定课程查询所有待审关联只对管理员开放。

## 7. 生成前证据注入

Resource Generation Agent 对每个目标知识点执行：

1. 优先取已确认的 `kp_chunk_links`。
2. 没有已确认关联时按知识点名称 BM25 检索。
3. 按 chunk ID 去重，按相关度排序，最多取 8 个证据分块。
4. 将标题、文件名、页码/段落、不超过 500 字的原文摘要和 chunk ID 注入 Prompt。
5. 要求模型对来自课程原文的关键结论使用 `[引用:chunk_id]`。

证据只来自当前 `course_id`，不将其他课程材料注入 Prompt。

## 8. 生成后引用校验

### 8.1 引用提取

只识别整数格式 `[引用:123]`。每个 ID 必须存在于本次检索到的证据集中才算有效。其他文字、开发降级的字符串 ID 或模型自行构造的数字不会生成证据关联。

### 8.2 可信等级

| 条件 | 等级 | 处理 |
| --- | --- | --- |
| 没有任何引用 | `draft` | 提示缺少课程来源锚点，必须由教师核验 |
| 有效引用覆盖率低于 50% | `low` | 记录引用丢失风险 |
| 引用中含无效 chunk ID | `medium` | 忽略无效 ID，保留告警 |
| 所有引用均对应本次证据 | `high` | 生成可持久化证据关联，仍需教师审核 |

当课程上下文可用且生成内容足够长时，Agent 还会调用一次对比检查，返回可疑结论警告。该检查是风险提示，不是数学证明或自动发布许可。

## 9. 资源证据持久化

对每个有效引用，系统构建：

- 真实整数 `chunk_id`
- 对应 `kp_id`
- 最多 200 字的原文摘要
- 相关度分数
- `direct_quote` 或 `paraphrase` 使用方式
- 来源页码与段落

`POST /api/agents/save-resource` 在同一 MySQL 事务中保存资源和证据关联。证据不存在、不属于当前课程/知识点或资源保存失败时，整体回滚。

教师在审核界面可以查看证据原文和来源，并将关联标记为 `verified` 或 `rejected`。材料重新解析后，旧证据变为 `replaced`，避免将已过期 chunk 继续显示为当前来源。

## 10. 权限模型

| 操作 | 学生 | 教师 | 管理员 |
| --- | --- | --- | --- |
| 列表/搜索可见课程材料 | 已关联课程 | 本人课程 | 全部课程 |
| 上传、解析、删除 | 禁止 | 本人课程 | 允许 |
| 审核知识点关联 | 禁止 | 本人课程 | 允许 |
| 查看资源证据 | 本人可见资源 | 本人课程资源 | 允许 |
| 验证资源证据 | 禁止 | 本人课程 | 允许 |

每个 API 先验证角色，再通过 `CourseAccessService` 验证课程、材料、知识点关联、资源或证据的实际所有权。

## 13. 局限与扩展条件

| 当前边界 | 处理方式 | 扩展触发条件 |
| --- | --- | --- |
| 扫描 PDF 无 OCR | 显式报告无可提取文本 | 真实课程材料大量为扫描件时接入 OCR |
| BM25 主要基于词法匹配 | 知识点确认、中文 n-gram 和教师审核弥补 | 用离线检索评估集证明语义召回不足时引入混合检索 |
| 本地文件存储为单节点 | Docker 持久卷备份 | 多 Backend 副本或跨节点容灾时迁移对象存储 |
| 外部 ChatDoc 需真实凭证 | 本地知识库独立可运行，缺凭证时不伪造外部结果 | 服务开通后作为可选外部能力联调 |

任何扩展都必须保留整数 chunk ID、课程所有权、证据审核和无证据降级规则。
