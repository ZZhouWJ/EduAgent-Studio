# 03_阶段任务卡与验收清单

文档版本：v1.0  
用途：控制 AI 开发节奏，防止一次性生成全项目、跑偏技术栈、遗漏测试。  
使用方式：每次只复制当前阶段任务卡给 AI，并同时附上 `00_AI开发总控规范.md` 与必要的 Schema / 接口文档。

---

## 0. 总执行原则

1. 每次只做一个阶段。
2. 每个阶段只修改允许修改的文件。
3. 每个阶段必须给出运行方法和测试方法。
4. 每个阶段必须满足验收标准后才能进入下一阶段。
5. 不允许跳过数据库直接写前端。
6. 不允许一开始做 UI 美化。
7. 不允许一次性生成全项目。
8. 所有代码必须可运行。
9. 所有 SQL 必须可执行。
10. 所有接口必须可测试。

## 1. AI 通用任务提示词

每次给 AI 编程助手任务时，先贴下面这段：

```text
你现在是本项目的代码实现助手，不是产品经理，也不是架构师。

你必须严格遵守：
1. docs/00_AI开发总控规范.md
2. docs/01_数据库Schema冻结说明.md
3. docs/02_接口契约与页面清单.md
4. 当前阶段任务卡

禁止自行修改技术栈。
禁止自行新增未确认的数据表。
禁止自行重命名字段。
禁止把系统做成普通聊天系统。
禁止使用未声明依赖。
禁止一次性生成整个项目。
禁止用伪代码代替可运行代码。

如果你发现需求不明确，必须先列出问题，不能自行脑补。
本次只完成任务卡中指定的内容。
```

## 2. AI 输出格式要求

AI 每次必须按以下结构回答：

```text
一、本次修改范围
二、涉及文件
三、实现思路
四、完整代码
五、数据库影响
六、运行步骤
七、测试步骤
八、验收清单
九、风险与回滚方式
```

| 阶段 | 名称 | 允许修改范围 | 目标 | 验收重点 |

# Stage-01 数据库脚本

## 任务目标

实现系统数据库基础结构，包括建库、建表、索引、初始化数据、视图、触发器、存储过程和测试查询。

## 允许修改

```text
database/01_create_database.sql
database/02_create_tables.sql
database/03_create_indexes.sql
database/04_insert_initial_data.sql
database/05_create_views.sql
database/06_create_stored_procedures.sql
database/07_test_queries.sql
```

## 禁止修改

```text
backend/*
frontend/*
docs/00_AI开发总控规范.md
docs/01_数据库Schema冻结说明.md
```

## 验收标准

1. SQL 文件可以按顺序执行；
2. 所有表成功创建；
3. 外键约束无错误；
4. 初始化数据插入成功；
5. 能执行至少 5 条典型查询；
6. 能查询项目任务统计视图；
7. 能调用项目归档存储过程；
8. 审核通过触发器能写入操作日志；
9. 不出现未定义表名和字段名。

## 推荐提示

```text
请只完成 Stage-01 数据库脚本。你只能修改 database/ 目录下的 SQL 文件。请严格按照 docs/01_数据库Schema冻结说明.md 建表。不要写后端，不要写前端。不要自行新增未确认字段。
```

# Stage-02 后端基础框架

目标：搭建 FastAPI 项目结构，实现数据库连接、统一返回格式、配置读取、基础异常处理和健康检查接口。

允许修改：`backend/app/main.py`、`backend/app/config.py`、`backend/app/database.py`、`backend/app/utils/response.py`、`backend/app/utils/exceptions.py`、`backend/requirements.txt`、`backend/run.py`。

验收：服务能启动；`/api/health` 返回 success；数据库连接测试成功；依赖明确；无业务表结构修改。

---

# Stage-03 用户登录与权限

目标：实现登录、当前用户、用户管理、角色分配、权限校验基础能力。

涉及表：`users`、`roles`、`user_roles`、`permissions`、`role_permissions`、`login_logs`、`operation_logs`。

验收：正确账号可登录；错误密码登录失败；登录日志可查；管理员可创建用户；管理员可分配角色；普通用户不能访问用户管理页。

---

# Stage-04 项目空间管理

目标：实现项目创建、项目列表、项目详情、成员添加、成员移除、项目归档入口。

涉及表：`projects`、`project_members`、`users`、`operation_logs`。

验收：可创建项目；可查看项目详情；可添加成员；可移除成员；普通成员不能看到无关项目；归档项目后状态正确。

---

# Stage-05 任务与版本管理

目标：实现任务创建、任务列表、任务详情、分支创建、输出版本列表、版本时间线查询。

涉及表：`project_tasks`、`task_branches`、`task_outputs`、`task_types`、`operation_logs`。

验收：可创建任务；可查看项目任务列表；可创建分支；可查看输出版本列表；可查看版本时间线；不产生聊天式 UI。

---

# Stage-06 提示词模板管理

目标：实现提示词模板列表、创建模板、创建版本、启用版本。

涉及表：`task_types`、`prompt_templates`、`prompt_versions`、`operation_logs`。

验收：可查看任务类型；可按任务类型筛选模板；可新增模板；可新增模板版本；可启用版本；启用后 current_version_id 正确。

---

# Stage-07 模型调用与调用日志

目标：实现 Mock ModelAdapter，完成一次 AI 生成流程。

涉及表：`model_providers`、`ai_models`、`api_configs`、`ai_invocations`、`task_outputs`、`cost_records`、`operation_logs`。

验收：选择 Mock 模型可以生成结果；生成结果进入输出版本；调用日志可查询；成本记录正确；失败调用也有日志。

---

# Stage-08 人工编辑与乐观锁

目标：实现人工创建版本、编辑版本、保存修改说明、乐观锁冲突提示。

涉及表：`task_outputs`、`output_comments`、`operation_logs`。

验收：可人工创建内容；可基于 AI 版本创建混合修改版；可编辑并保存；模拟两个页面同时编辑时能触发冲突；批注可新增、查看、关闭。

---

# Stage-09 审核中心

目标：实现提交审核、审核评分、问题标签、退回与通过。

涉及表：`review_requests`、`output_reviews`、`issue_tags`、`output_issue_relations`、`task_outputs`、`project_tasks`、`operation_logs`。

验收：可提交审核；审核中心显示待审核；可评分；可标注问题；通过后状态正确；退回后状态正确；日志正确。

---

# Stage-10 成果库与分支合并

目标：实现成果采用、成果库、分支冲突处理、合并记录。

涉及表：`adopted_outputs`、`merge_records`、`task_outputs`、`task_branches`、`operation_logs`。

验收：可采用成果；成果库显示采用结果；可查看成果来源；可处理两个同源版本冲突；合并日志可查。

---

# Stage-11 统计看板

目标：实现首页仪表盘、模型统计、成本统计、成员贡献排行。

涉及表：`projects`、`project_tasks`、`ai_invocations`、`cost_records`、`output_reviews`、`adopted_outputs`、`operation_logs`。

验收：首页显示统计卡片；图表能正常渲染；数据来自数据库；筛选条件有效；无硬编码假数据。

---

# Stage-12 系统测试与报告截图

目标：完成系统测试用例和课程报告所需截图素材。

测试清单：登录测试、权限测试、项目创建测试、成员添加测试、任务创建测试、Mock 模型生成测试、人工编辑测试、乐观锁冲突测试、提交审核测试、审核通过测试、审核退回测试、成果采用测试、分支合并测试、调用日志测试、统计看板测试、软删除测试、项目归档测试。

截图要求：登录页、首页仪表盘、项目列表、项目详情、任务详情、AI 生成页面、人工编辑页面、版本时间线、审核中心、成果库、调用日志、模型管理、用户管理、数据库表结构、关键 SQL 执行结果。
