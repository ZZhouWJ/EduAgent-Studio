# 智研协作 AI 项目质量审计系统结课报告

## 摘要

“智研协作 AI 项目质量审计系统”是面向高校课程设计、团队项目协作与 AI 生成内容质量管理的数据库课程设计系统。系统围绕“项目空间、任务管理、AI 生成、版本追踪、人工编辑、批注协作、审核评分、成果采用、调用审计、成本统计和统计看板”构建完整业务闭环，目标是在高校项目协作场景下解决 AI 输出难追踪、多人协作版本混乱、审核过程缺乏记录、成果沉淀不清晰和模型调用成本不可见等问题。

系统采用前后端分离架构。后端基于 FastAPI 实现统一接口、认证授权、业务服务、Repository 层和参数化 SQL 访问；前端基于 V3 Admin Vite 开源 Vue3 后台模板二次开发，使用 Vue3、Vite、TypeScript、Element Plus、Pinia 和 Vue Router 构建后台管理界面；数据库使用 MySQL 8.0，核心业务数据存储在 `ai_collab_audit_system` 数据库中。数据库设计包含 27 张主业务表，覆盖用户、角色、权限、项目、成员、任务、分支、输出版本、提示词模板、模型、API 配置、调用记录、成本记录、审核请求、审核记录、问题标签、批注、成果库、分支合并、操作日志和登录日志等对象。

本系统在数据库课程设计方面重点体现了关系模型设计、主键与外键约束、唯一约束、索引设计、软删除与审计字段、视图、触发器、存储过程、事务一致性、乐观锁并发控制、参数化 SQL、防敏感信息泄露、操作日志和统计聚合查询等内容。当前远程资料显示，项目已完成主要开发和静态审查，后端阶段、前端阶段、文档与截图素材阶段以及成熟产品化修复已完成；但 Windows MySQL 数据库导入、前后端完整联调与截图仍需在本地 Windows MySQL + Node 环境中补做验证。

## 1 系统开发背景与意义

随着大模型工具在高校课程设计、毕业设计和团队项目中的普及，学生可以借助 AI 快速生成需求分析、数据库设计、代码片段、文档章节、测试用例和项目总结。AI 提升了初稿生成效率，但也带来了新的管理问题：AI 输出来源不清晰、不同模型结果难以比较、多人修改版本难追踪、审核意见容易散落在聊天记录或文档批注中、最终成果缺乏统一沉淀，且模型调用成本与质量数据缺少统计支撑。

在传统高校项目协作中，项目负责人、普通成员、评审人员和指导教师通常通过即时通信工具、文档平台或代码仓库协作。这些工具虽然能完成基本沟通，但难以围绕“AI 生成内容”建立全过程数据链路。例如，某段报告内容究竟由哪个模型生成、由谁编辑、经过几轮审核、是否被采用为最终成果、消耗了多少 token 和成本，这些信息往往不可追溯。

本系统的建设意义主要体现在以下几个方面。

第一，系统将 AI 生成内容纳入项目任务和版本管理体系，使 AI 输出不再是孤立文本，而是绑定到项目、任务、分支和输出版本。每次 AI 生成都会形成 `ai_invocations` 调用记录，并在成功时生成 `task_outputs` 输出版本。

第二，系统提供人工编辑、另存为新版本和乐观锁机制。用户可以在输出版本上进行人工修改，并通过 `lock_version` 防止并发覆盖，保留修改摘要和最后修改人信息。

第三，系统建立批注与审核闭环。项目成员可对输出新增批注，评审人员或指导教师可发起审核、填写评分、关联问题标签，并通过 `review_requests`、`output_reviews`、`output_issue_relations` 等表保留审核证据。

第四，系统支持成果采用和成果库沉淀。审核通过的输出可以被采用为项目成果，写入 `adopted_outputs`，并保留来源项目、任务、输出版本、采用人和采用时间。

第五，系统记录模型调用审计与成本统计。通过 `ai_invocations` 和 `cost_records`，可以统计调用次数、成功率、token 消耗、模型成本、项目成本和成员贡献，为教学评估和项目管理提供数据依据。

因此，本系统不仅是一个 AI 生成平台，更是一个围绕高校项目协作和质量审计设计的数据管理系统，能够体现数据库课程设计中从需求分析、数据库设计到业务实现和测试验证的完整过程。

## 2 需求分析

### 2.1 用户角色分析

系统用户主要包括以下角色。

1. 管理员：负责用户管理、角色权限管理、模型管理、API 配置、系统日志和全局统计查看。管理员可以跨项目查看和管理数据。
2. 普通成员：通常是学生项目成员，可以参与项目、创建或承担任务、发起 AI 生成、编辑输出、另存版本、添加批注和查看与自己相关的审核记录。
3. 项目负责人：在具体项目内承担 `project_members.project_role = leader` 的用户，可以管理项目成员、创建和管理任务、组织审核、采用成果和执行分支合并。学生也可能是某项目负责人。
4. 审核人员：在项目内承担 `reviewer` 角色或被指定为审核人的用户，可以查看授权范围内的审核请求并完成审核评分。
5. 指导教师：在项目内承担 `teacher` 角色的用户，可以查看和指导项目，参与审核、成果采用和质量评价。教师身份并不意味着对所有项目都有指导权限，项目级权限仍以 `project_members.project_role` 为准。

系统同时区分全局角色和项目内角色。全局角色用于控制用户管理、模型管理、系统日志等系统级入口；项目内角色用于控制项目详情、成员管理、任务管理、审核、成果采用和分支合并等项目级操作。

### 2.2 功能需求

系统功能需求包括：注册与登录、用户与权限、项目空间、任务与版本、AI 生成、提示词模板、模型管理、输出编辑与批注、审核中心、成果库、分支合并、调用审计、成本统计、操作日志、登录日志和统计看板。

注册与登录模块需要支持 `POST /api/auth/register`、`POST /api/auth/login`、`GET /api/auth/me`、`PUT /api/auth/me/password` 和 `POST /api/auth/logout`。注册时校验 `confirm_password`，密码使用哈希存储，注册用户默认分配普通成员角色，接口不返回 `password_hash`。

项目空间模块需要支持项目列表、创建项目、项目详情、项目更新、项目软删除、项目归档、项目成员列表、添加成员、修改成员角色、移除成员和项目相关操作日志。

任务与版本模块需要支持项目任务列表、创建任务、任务详情、更新任务、软删除任务、创建分支、分支列表、输出版本列表、输出详情、输出时间线、人工输出版本创建、AI 输出生成和版本链追踪。

AI 生成模块需要支持模型选择、提示词模板和版本选择、输入文本、Mock 模型调用、`ai_invocations` 写入、`task_outputs` 写入、`cost_records` 写入和 operation_logs 写入。

审核中心模块需要支持输出提交审核、待审核列表、审核详情、完成审核、评分写入、问题标签关联、输出状态更新和任务状态更新。成果库模块需要支持采用成果、成果列表、成果详情、分支合并和合并记录。

统计看板模块需要支持首页概览、项目统计、模型调用统计、成本统计、审核质量统计、成员贡献排行和最近操作动态。

### 2.3 数据需求

系统需要保存用户账号、角色、权限、项目、项目成员、任务类型、任务、提示词模板、提示词版本、模型供应商、AI 模型、API 配置、任务分支、模型调用记录、输出版本、审核请求、审核记录、问题标签、输出标签关联、输出批注、成果库、分支合并记录、成本记录、操作日志和登录日志等数据。

所有核心业务表需要具备可追溯性。多数核心表包含 `is_deleted`、`deleted_at`、`deleted_by`、`created_at`、`created_by`、`updated_at`、`updated_by` 等软删除和审计字段。部分日志和统计类表如 `ai_invocations`、`cost_records`、`operation_logs`、`login_logs` 保留记录型字段，以保证审计追踪。

### 2.4 权限需求

系统权限分为系统级权限和项目级权限。系统级权限由 `users`、`roles`、`user_roles`、`permissions`、`role_permissions` 共同维护；项目级权限由 `project_members.project_role` 决定。项目角色固定为 `member`、`leader`、`reviewer`、`teacher`。

前端根据用户角色和项目内角色控制菜单、路由入口和按钮显示；后端接口仍作为最终权限控制点。管理员拥有全局管理权限；非管理员只能查看或操作自己参与项目范围内的数据。

### 2.5 审计需求

系统需要记录登录行为、业务操作、AI 调用、模型成本、审核评分和成果采用。登录行为写入 `login_logs`，字段包括 `username`、`login_status`、`failure_reason`、`ip_address`、`user_agent`、`login_time`。业务操作写入 `operation_logs`，包括操作人、项目、任务、目标类型、目标 ID、操作类型、操作描述、旧值、新值、IP 和 UA。

### 2.6 非功能需求

系统需要满足安全性、可维护性、可扩展性、可审计性和教学可展示性。安全性方面，密码哈希存储，JWT 用于登录状态，API Key 采用 AES-GCM 加密保存并仅展示脱敏 `key_mask`。可维护性方面，后端采用 Router、Service、Repository 分层，SQL 集中在 Repository 层并使用参数化查询。教学可展示性方面，系统提供完整的前端页面、文档、接口清单、测试素材和截图清单。

## 3 系统总体设计

### 3.1 系统总体架构

系统采用前后端分离架构，整体分为前端展示层、后端服务层、数据库层、AI 调用适配层和审计统计层。

[图3-1：系统总体架构图，待本地运行后补充]

该图用于展示 Vue3 前端、FastAPI 后端、MySQL 数据库、Mock ModelAdapter、审计日志与统计查询之间的关系。

前端展示层基于 Vue3 和 V3 Admin Vite 模板二次开发，负责登录注册、项目空间、任务工作台、AI 生成、审核中心、成果库和统计看板等界面交互。

后端服务层基于 FastAPI，实现统一响应、JWT 鉴权、异常处理、业务服务和数据库访问。后端将业务逻辑放在 Service 层，将 SQL 查询和写入放在 Repository 层。

数据库层使用 MySQL 8.0，数据库名为 `ai_collab_audit_system`。所有主要业务数据均存储在关系表中，通过主键、外键、唯一约束、索引、软删除、审计字段和事务保证数据完整性。

AI 调用适配层当前采用 Mock ModelAdapter，不直接调用外部真实大模型。系统通过 MockWriterAdapter、MockCodeAdapter、MockReviewerAdapter 模拟写作型、代码解释型和审核建议型模型输出，便于课程环境演示和成本审计。

审计统计层由 `ai_invocations`、`cost_records`、`operation_logs`、`login_logs`、`output_reviews` 等表提供数据基础，后端统计模块通过聚合 SQL 实现项目统计、模型调用统计、成本统计、审核质量统计、成员贡献统计和最近动态。

### 3.2 业务流程设计

系统核心流程可以概括为：用户注册或登录后进入项目空间，创建项目并添加成员；项目内创建任务并自动生成默认分支；成员在任务详情中选择模型和提示词版本发起 AI 生成；生成结果写入输出版本；成员可人工编辑输出、另存为新版本和添加批注；输出提交审核后，审核人员完成评分并给出意见；审核通过的输出可被采用为成果；成果进入成果库沉淀；分支之间可通过 adopt_source、adopt_target、manual_merge、adopt_separately 等策略合并；整个过程持续产生调用审计、成本记录、操作日志和统计数据。

[图4-1：系统 E-R 图，待本地运行后补充]

该图用于展示用户、项目、任务、输出版本、审核记录、成果库和日志之间的一对多或多对多关系。

## 6 数据库物理设计与完整性约束

### 6.1 主键设计

系统所有主业务表均使用自增整数主键，例如 `users.user_id`、`projects.project_id`、`project_tasks.task_id`、`task_outputs.output_id`、`review_requests.request_id`、`output_reviews.review_id`、`adopted_outputs.adopted_id`、`merge_records.merge_id`。自增主键便于业务关联、日志追踪和前端路由参数传递。

### 6.2 外键设计

系统通过外键约束保证实体关系。例如，`project_tasks.project_id` 关联 `projects.project_id`，`project_members.user_id` 关联 `users.user_id`，`task_outputs.task_id` 关联 `project_tasks.task_id`，`review_requests.output_id` 关联 `task_outputs.output_id`，`output_reviews.request_id` 关联 `review_requests.request_id`，`adopted_outputs.output_id` 关联 `task_outputs.output_id`。这些外键约束保证数据引用的一致性，避免出现无项目任务、无任务输出、无输出审核等孤立记录。

### 6.3 唯一约束

系统设置了多处唯一约束，例如 `users.username`、`users.student_no`、`users.email`、`roles.role_code`、`permissions.permission_code`、`project_members(project_id, user_id, is_deleted)`、`prompt_versions(template_id, version_no)`、`ai_models(provider_id, model_name, is_deleted)`。这些约束用于防止账号重复、角色权限代码重复、同一项目重复添加同一未删除成员、同一模板版本号重复和同一供应商下模型重复。

### 6.4 索引设计

`database/03_create_indexes.sql` 提供了普通二级索引设计，用于提升用户查询、项目查询、任务查询、输出版本查询、审核查询、调用日志查询和统计聚合查询的效率。课程设计阶段已经检查过重复索引问题，`idx_tasks_creator` 等普通索引统一放在索引脚本中。

### 6.5 软删除与审计字段

核心业务表普遍包含 `is_deleted`、`deleted_at`、`deleted_by`、`created_at`、`created_by`、`updated_at`、`updated_by`。软删除设计可以保留历史数据和审计证据，避免物理删除导致审核链路、成果来源或统计记录断裂。

### 6.6 时间字段与状态字段

系统中常见时间字段包括 `created_at`、`updated_at`、`deleted_at`、`last_login_at`、`joined_at`、`reviewed_at`、`adopted_at`、`merged_at`、`login_time`。状态字段包括项目状态、任务状态、输出状态、审核请求状态、审核结果状态、批注状态、模型状态等。系统通过枚举约束和业务校验确保状态值与冻结文档保持一致。

## 7 数据库高级特性设计

### 7.1 视图设计

`database/05_create_views.sql` 创建了多个视图，包括 `v_project_task_statistics`、`v_model_invocation_statistics`、`v_pending_reviews`、`v_user_permissions` 和 `v_artifacts`。这些视图将常用多表查询封装为可复用查询对象，便于统计、审核列表、用户权限展示和成果库展示。

`v_project_task_statistics` 用于项目任务统计，聚合任务数量、输出数量和审核请求数量；`v_model_invocation_statistics` 用于模型调用统计；`v_pending_reviews` 用于待审核列表；`v_user_permissions` 用于用户角色权限查询；`v_artifacts` 用于成果库查询。

### 7.2 触发器设计

`database/06_create_stored_procedures.sql` 中定义了 `trg_output_review_approved`、`trg_output_review_rejected`、`trg_output_review_revision_required` 等触发器，用于在审核记录状态变化时辅助维护业务状态或写入日志。触发器体现了数据库层对关键质量状态变化的自动响应能力。

### 7.3 存储过程设计

系统定义了多个存储过程，包括 `sp_archive_project`、`sp_create_project_with_owner`、`sp_submit_output_for_review`、`sp_complete_review` 和 `sp_adopt_output`。这些存储过程封装了项目归档、创建项目并设置负责人、提交审核、完成审核和采用成果等关键业务流程。

其中 `sp_archive_project` 用于项目归档，将项目状态更新为 archived，并关联处理项目任务和任务分支状态；`sp_create_project_with_owner` 用于在创建项目时同时写入项目负责人关系；`sp_submit_output_for_review` 和 `sp_complete_review` 用于审核提交与完成；`sp_adopt_output` 用于成果采用。

### 7.4 事务设计

后端业务写操作使用 `get_db_transaction()` 保证原子性。例如，注册流程在同一事务中完成 `users` 插入、`user_roles` 分配和 `operation_logs` 写入；创建项目在同一事务中完成项目插入、项目成员写入和日志记录；创建任务在同一事务中写入任务、默认分支和日志；完成审核在同一事务中写入 `output_reviews`、更新 `review_requests`、更新 `task_outputs`、更新 `project_tasks`、写入问题标签关系和操作日志；成果采用和分支合并也在事务中处理状态更新和日志写入。

### 7.5 乐观锁设计

输出编辑使用 `task_outputs.lock_version` 实现乐观锁。前端提交编辑时携带当前 `lock_version`，后端更新条件包含 `output_id`、`lock_version` 和 `is_deleted = 0`。更新成功后 `lock_version = lock_version + 1`；如果 affected_rows 为 0，则返回业务错误码 4004，提示“当前内容已被其他成员修改，请刷新后重新编辑，或另存为新版本。”该设计避免多人同时编辑同一输出时出现覆盖更新。

### 7.6 参数化 SQL 与安全查询

项目采用 Repository 层集中编写 SQL，并使用 `%s` 占位符参数化执行，避免直接拼接用户输入。前端请求参数经过后端 Query 或 Pydantic 模型接收后再传入 Repository 层，降低 SQL 注入风险。

### 7.7 审计与统计查询

操作日志、登录日志、调用日志、成本记录和审核评分共同构成审计数据源。统计模块基于 `COUNT`、`SUM`、`AVG`、`GROUP BY`、`LEFT JOIN`、`CASE WHEN` 等 SQL 聚合实现项目统计、模型调用统计、成本统计、审核质量统计、成员贡献统计和最近操作动态。

## 8 系统功能模块设计与实现

### 8.1 注册与登录模块

系统提供 `POST /api/auth/register` 注册接口，前端对应 `/register` 页面。注册表单包含用户名、真实姓名、学号、邮箱、手机号、密码和确认密码。后端 `RegisterRequest` 接收 `confirm_password` 并在 Service 层校验两次密码一致。密码通过 `hash_password` 哈希存储，不明文入库。注册流程使用事务，在同一事务中写入用户、角色关联和操作日志。注册成功后不直接返回 token，用户需进入登录页登录。

登录接口为 `POST /api/auth/login`。用户输入用户名和密码后，后端校验 `users.password_hash`，成功后生成 JWT token，并写入 `login_logs`。登录失败同样写入登录日志，失败原因字段为 `failure_reason`。`GET /api/auth/me` 根据 Authorization Bearer token 返回当前用户基本信息、角色和权限，不返回 `password_hash`。`POST /api/auth/logout` 写入登出日志并返回统一成功格式。

系统还提供 `PUT /api/auth/me/password` 修改密码接口，后端通过 `get_user_by_id_with_password` 获取 `password_hash` 用于旧密码验证，新密码重新哈希后保存。

### 8.2 用户与权限管理模块

用户管理模块提供用户列表、启用禁用、角色分配、角色列表和权限列表等功能。后端接口包括 `GET /api/users`、`PUT /api/users/{id}/status`、`PUT /api/users/{id}/roles`、`GET /api/roles`、`GET /api/permissions`。用户列表不返回 `password_hash`。

前端通过 `/users` 页面展示用户列表、搜索、状态筛选、启用禁用和角色分配。路由层通过 `meta.roles` 控制用户管理仅管理员可见。前端还提供 `/profile` 个人中心，用于展示用户资料、角色和修改密码。

### 8.3 项目空间模块

项目空间模块提供项目列表、项目创建、项目详情、项目更新、项目归档、项目成员列表、添加成员、修改成员角色、移除成员和项目统计展示。后端项目接口位于 `/api/projects` 下，创建项目时创建人自动成为项目成员并拥有 leader 角色。

前端 `/projects` 页面展示项目列表、搜索和创建项目弹窗。项目详情页 `/projects/:projectId` 采用多 Tab 布局，展示项目概览、成员、任务、成果、调用、日志和统计。项目成员管理根据当前用户项目内角色控制按钮显示。项目成员角色使用 `project_members.project_role`，包括 `member`、`leader`、`reviewer`、`teacher`。

### 8.4 任务与版本管理模块

任务模块包括项目任务列表、创建任务、任务详情、任务更新、软删除、分支列表、创建分支、输出版本列表、输出详情、输出时间线和人工输出版本。创建任务接口为 `POST /api/projects/{project_id}/tasks`，请求字段使用 `task_type_id`、`title`、`description`、`assignee_id`、`priority`、`due_date`。创建成功后自动创建默认任务分支。

任务详情页 `/tasks/:taskId` 展示任务基础信息、所属项目信息、分支列表和输出版本列表。输出版本列表兼容数组返回和分页返回，任务类型字段使用后端真实字段 `type_name`。输出详情通过 `GET /api/outputs/{output_id}` 获取完整内容，并可查看 `lock_version`、`source_type`、`status`、`created_at` 等信息。

版本时间线接口为 `GET /api/outputs/{output_id}/timeline`，基于 `parent_output_id` 向上追溯父版本链。另存为新版本接口为 `POST /api/outputs/{output_id}/save-as-new-version`，不能使用旧的 `/save-as` 作为正式接口。

### 8.5 AI 生成模块

AI 生成模块通过 `POST /api/tasks/{task_id}/generate` 完成。前端提供模型选择、提示词模板选择、提示词版本选择、分支选择和输入文本区域，请求体包括 `branch_id`、`model_ids`、`prompt_version_id` 和 `input_text`。后端当前使用 Mock ModelAdapter，不直接调用外部真实大模型。

生成过程会为每个模型写入 `ai_invocations`。成功调用会写入 `task_outputs`，并记录 `source_type = ai_generated`、`invocation_id`、`version_no`、`lock_version`、`last_modified_by` 和 `last_modified_at`。无论成功或失败，都需要保留调用审计；成本记录写入 `cost_records`，失败调用成本可为 0。

### 8.6 提示词模板模块

提示词模板模块包括任务类型列表、提示词模板列表、模板创建、模板详情、模板更新、软删除、创建提示词版本、版本列表和启用版本。相关接口包括 `GET /api/task-types`、`GET /api/prompt-templates`、`POST /api/prompt-templates`、`GET /api/prompt-templates/{template_id}`、`PUT /api/prompt-templates/{template_id}`、`DELETE /api/prompt-templates/{template_id}`、`GET /api/prompt-templates/{template_id}/versions`、`POST /api/prompt-templates/{template_id}/versions`、`POST /api/prompt-templates/{template_id}/versions/{version_id}/activate`。

系统额外提供 `database/08_insert_prompt_templates.sql` 和 `database/import_prompts.py`，用于初始化 24 个面向高校项目协作和数据库课程设计场景的提示词模板。该脚本不修改数据库结构，只写入模板数据。提示词搜索参数使用 `keyword`。

### 8.7 模型管理模块

模型管理模块包括模型供应商、AI 模型和 API 配置。供应商接口包括 `GET /api/model-providers` 和 `POST /api/model-providers`；模型接口包括 `GET /api/ai-models` 和 `POST /api/ai-models`；API 配置接口包括 `GET /api/api-configs` 和 `POST /api/api-configs`。

`ai_models` 表包含 `input_price`、`output_price`、`price_unit` 等计费字段。`api_configs` 表保存 `encrypted_api_key`、`key_iv`、`key_tag`、`key_version` 和 `key_mask`，后端通过 AES-GCM 加密 API Key，前端只展示脱敏字段，不展示明文密钥或加密细节。

### 8.8 输出编辑与批注模块

输出编辑接口为 `PUT /api/outputs/{output_id}`，请求体包含 `content`、`lock_version` 和 `edit_summary`。后端通过乐观锁控制并发，成功后更新内容、修改摘要、最后修改人和锁版本。

另存为新版本接口为 `POST /api/outputs/{output_id}/save-as-new-version`，新版本的 `parent_output_id` 指向原输出，保留原版本不变。批注接口包括 `GET /api/outputs/{output_id}/comments`、`POST /api/outputs/{output_id}/comments` 和 `PUT /api/comments/{comment_id}/status`。批注类型只能使用 `comment`、`suggestion`、`approval`，批注状态只能使用 `open`、`resolved`、`closed`。

### 8.9 审核中心模块

审核中心支持输出提交审核、待审核列表、审核详情、完成审核和问题标签。提交审核接口为 `POST /api/outputs/{output_id}/submit-review`，完成审核接口为 `POST /api/reviews/{request_id}/complete`。审核结果状态只允许 `approved`、`rejected`、`revision_required`。

完成审核时，系统写入 `output_reviews`，更新 `review_requests.request_status`、`task_outputs.status` 和 `project_tasks.status`，并可将问题标签写入 `output_issue_relations`。评分字段包括准确性、完整性、逻辑性、格式规范、可用性和风险等，范围为 0 到 10。审核通过不会直接写入 `adopted_outputs`，成果采用属于成果库流程。

### 8.10 成果库模块

成果库模块用于沉淀审核通过并被正式采用的输出。采用接口为 `POST /api/outputs/{output_id}/adopt`，项目成果列表接口为 `GET /api/projects/{project_id}/artifacts`，成果详情接口为 `GET /api/artifacts/{adopted_id}`。

采用成果前需要确认输出状态为 approved，采用后写入 `adopted_outputs`，并更新 `task_outputs.status = adopted` 与 `project_tasks.status = adopted`。前端成果库页面支持成果列表、筛选、详情查看和 Markdown 导出等演示功能。

### 8.11 分支合并模块

分支合并接口为 `POST /api/tasks/{task_id}/branches/merge`，合并记录写入 `merge_records`。合并策略包括 `adopt_source`、`adopt_target`、`manual_merge` 和 `adopt_separately`。`adopt_source` 需要源输出，`adopt_target` 需要目标输出，`manual_merge` 需要人工合并标题和内容，`adopt_separately` 至少保留一个输出。合并过程需要校验分支和输出均属于当前任务，避免跨任务或跨项目合并。

### 8.12 调用审计与成本统计模块

调用审计接口包括 `GET /api/invocations` 和 `GET /api/invocations/{invocation_id}`。调用记录展示项目、任务、模型、调用状态、token、延迟和错误信息。当前调用审计列表支持 `project_id`、`task_id`、`model_id` 和 `status` 筛选，文档说明暂不支持日期筛选。

成本统计基于 `cost_records`，系统根据模型的输入单价、输出单价和 `price_unit` 计算输入成本、输出成本和总成本。统计接口 `GET /api/statistics/costs` 返回 `total_cost`、`input_cost`、`output_cost`、`total_tokens`、`cost_by_model`、`cost_by_project`、`cost_by_user` 等字段。

### 8.13 操作日志与登录日志模块

操作日志接口为 `GET /api/logs/operation`，登录日志接口为 `GET /api/logs/login`。操作日志记录业务操作人、目标对象、操作描述、旧值、新值、IP 和 UA。登录日志记录用户名、登录状态、失败原因、IP、UA 和登录时间。前端提供操作日志和登录日志页面，用于课程演示和系统审计展示。

### 8.14 统计看板模块

统计接口包括 `GET /api/statistics/overview`、`GET /api/statistics/projects`、`GET /api/statistics/model-calls`、`GET /api/statistics/costs`、`GET /api/statistics/reviews`、`GET /api/statistics/member-contributions` 和 `GET /api/statistics/recent-activities`。

统计看板展示项目数量、活跃项目、任务数量、待审核数量、调用数量、成功/失败调用、成果数量、总 token、总成本、模型调用统计、成本分布、审核质量、成员贡献排行和最近操作动态。非管理员只能查看自己参与项目范围内的数据。

## 11 系统安全性与可靠性设计

系统在安全性与可靠性方面采取了多项措施。

第一，密码哈希存储。用户注册和修改密码均通过 `hash_password` 保存哈希值，登录和修改密码通过 `verify_password` 校验，前端和普通接口不返回 `password_hash`。

第二，JWT 认证。用户登录成功后后端生成 token，前端保存 token 并在请求拦截器中携带 Authorization Header。token 无效或过期时前端跳转登录页。

第三，权限控制。后端通过用户角色、权限和项目成员关系控制访问；前端通过路由守卫、菜单权限和按钮权限提升用户体验，但后端仍作为最终安全边界。

第四，参数化 SQL。Repository 层统一使用参数化 SQL，避免拼接用户输入导致 SQL 注入。

第五，API Key 加密与脱敏。API 配置使用 AES-GCM 加密保存，数据库字段包括 `encrypted_api_key`、`key_iv`、`key_tag`、`key_version` 和 `key_mask`。前端不展示明文 API Key。

第六，操作日志和登录日志。系统记录用户登录、登出、注册、项目操作、任务操作、审核、成果采用和分支合并等行为，便于审计追溯。

第七，乐观锁与事务。输出编辑通过 `lock_version` 防止并发覆盖，多表写入通过事务保证一致性，失败时回滚。

## 12 系统特色与创新点

本系统的特色主要包括以下方面。

第一，AI 生成内容全过程管理。系统将 AI 生成绑定到项目、任务、分支、模型、提示词版本、调用记录和输出版本，实现从生成到审核再到成果采用的完整链路。

第二，引入 Git 式版本管理思想。任务分支、输出版本、父版本链和分支合并策略模拟了代码协作中的分支和合并机制，适合多人协作的课程项目管理。

第三，人工编辑与批注协作。系统并不把 AI 输出作为最终结果，而是支持人工编辑、另存为新版本、批注协作和修改摘要，体现人机协同。

第四，审核评分与问题标签。审核中心从准确性、完整性、逻辑性、格式、可用性和风险等维度评分，并可关联问题标签，为质量审计提供结构化数据。

第五，成果库沉淀。审核通过的输出可以被采用为项目成果，保留来源项目、来源任务、来源版本和采用记录，方便课程报告或项目结项管理。

第六，模型调用审计与成本统计。系统记录模型调用、token、延迟、状态、错误信息和成本，支持从模型、项目和用户多个维度分析 AI 使用情况。

第七，数据库设计完整。系统使用 27 张主业务表、视图、触发器、存储过程、事务、乐观锁、审计字段和统计查询，体现数据库课程设计的综合能力。

## 13 总结与展望

本项目围绕高校项目协作和 AI 质量审计场景，完成了一个较完整的数据库课程设计系统。从当前项目资料看，系统已具备注册登录、用户权限、项目管理、任务版本、AI 生成、提示词模板、模型管理、输出编辑、批注协作、审核评分、成果库、分支合并、调用审计、成本统计、操作日志和统计看板等功能。数据库结构覆盖业务主线，后端采用分层架构和参数化 SQL，前端采用成熟 Vue3 后台模板二次开发，文档、接口清单、测试素材和截图清单也已整理。

本项目的主要收获在于：通过一个具体业务系统，将数据库设计中的概念模型、逻辑模型、物理设计、约束设计、索引设计、视图、存储过程、触发器、事务、日志和统计查询结合起来；同时结合前后端工程实践，完成了可演示、可扩展和可审计的系统原型。

当前不足主要在于：真实外部大模型 API 尚未接入，当前使用 Mock ModelAdapter；数据库导入、接口联调和截图仍需在本地 Windows MySQL + Node 环境补做；权限控制还可以进一步细化到更多按钮和数据范围；统计图表也可以继续增强。

后续优化方向包括：增加邮箱验证注册和找回密码；引入更细粒度 RBAC/ABAC 权限模型；接入真实大模型 API；支持文档在线预览和导出；完善 E2E 自动化测试；增加更丰富的可视化图表；支持多租户和课程班级管理；部署到服务器并完成 HTTPS、日志轮转和备份策略。
