# AI Coding 工具使用说明

> 项目：智学工坊 EduAgent Studio
>
> 赛题：A3 基于大模型的个性化资源生成与学习多智能体系统开发
>
> 文档版本：V2.1，2026-07-17

## 1. 使用工具与边界

| 工具 | 在项目中的用途 | 交付边界 |
| --- | --- | --- |
| Cursor | 代码阅读、跨文件编辑、局部重构和交互式调试 | 不直接决定业务规则或跳过人工复核 |
| OpenAI Codex | 远程代码审计、问题修复、自动化测试、浏览器验证和文档同步 | 所有修改经 Git diff、针对性测试和全量门禁验证 |
| ChatGPT/Claude | 需求拆解、方案比较、文档初稿和风险检查 | 输出仅作候选方案，以赛题、代码和测试结果为最终依据 |

AI Coding 工具只进入软件工程流程，不代替教师对教学内容的审核，也不代替开发者对安全、数据一致性和发布质量的责任。

## 2. 实际使用场景

### 2.1 需求与架构

- 从 A3 赛题原文拆解学生画像、多智能体、个性化资源、学习路径、课程知识库与教师审核等验收项。
- 对照现有 React/FastAPI/MySQL 代码确定改造范围，避免将早期 Vue/PostgreSQL 方案误写为当前架构。
- 以三类角色的真实任务闭环检查页面，不以截图视觉完整代替业务可用性。

### 2.2 功能实现

- 辅助建立 Router → Service → Repository 的后端分层，使用参数化 SQL 访问 MySQL。
- 辅助实现 React 页面、Zustand 状态、统一 API 客户端、路由权限和响应式布局。
- 辅助实现 LangGraph 智能体工作流、LLM Gateway、SSE 进度事件、RAG 检索与资源证据链。
- 辅助将历史假数据页面改为真实 API 动作，并在测试后清理临时账号、资源、画像和会话数据。

### 2.3 质量与安全

- 根据失败用例生成最小修复，要求每个问题独立提交，便于审查和回滚。
- 补齐认证会话、越权访问、上传验证、调用参数、内容安全、RAG 召回和数据库迁移等自动化测试。
- 使用桌面和移动视口进行浏览器复核，检查路由、无名图标控件、横向溢出和控制台异常。
- 对依赖、构建、健康端点和数据库连接执行发布前验证。

## 3. 标准工作流

```text
赛题或产品需求
  → 阅读当前代码和数据模型
  → 确定可验收的行为与失败条件
  → 实施最小范围修改
  → 运行针对性测试和代码检查
  → 独立 Git 提交
  → 完成同等级问题后执行全量门禁并推送
  → 同步文档与参赛材料
```

关键原则：

1. 先阅读现有实现，再生成或修改代码。
2. 每次修复必须能由测试、API 响应、数据库状态或浏览器行为验证。
3. 不为了通过测试伪造结果，不把 Mock Provider 的结果宣称为真实讯飞调用。
4. 不覆盖与当前问题无关的未提交修改。

## 4. 代码与数据规范

### 4.1 前端

- React 18 + TypeScript + Vite，组件、路由和 API 类型保持一致。
- 认证状态由 Zustand store 统一管理，Axios 拦截器负责注入 Token 和处理会话失效。
- 所有图标按钮必须有可访问名称，三类角色页面必须在桌面与移动宽度下可用。
- Markdown 内容在渲染前进行消毒，不信任模型或用户输入的 HTML。

### 4.2 后端

- FastAPI Router 处理请求与权限，Service 处理业务规则，Repository 使用参数化 SQL 访问 MySQL。
- 资源、画像、学习进度和会话变更必须落库，同时维持业务所有权和角色权限。
- LLM 统一经由 Gateway 调用，密钥加密保存，输入与输出在启用时执行内容安全扫描。
- RAG 引用必须对应数据库中存在的文档分块；没有可用证据时，结果降级为草稿而不伪造引用。

### 4.3 密钥与测试数据

- 真实 API Key、密码、JWT 密钥和数据库口令只通过未跟踪的 `.env` 或部署密钥管理器注入。
- 不向 Prompt 提供生产密钥、真实学生隐私或无关的数据库记录。
- 端到端验证使用临时账号和唯一标识，验证后删除并恢复受影响的课程、资源和会话状态。

## 5. 验证门禁

```bash
# 后端
cd backend
PYTHONPATH=. python -m unittest discover -s tests -v
python -m compileall -q app tests
pip check

# 前端
cd frontend
npm run lint
npm run build
npm audit --omit=dev

# 运行状态
curl http://127.0.0.1:8000/api/health
curl http://127.0.0.1:8000/api/health/db
curl http://127.0.0.1:8000/api/health/redis
```

截至 2026-07-17，当前基线已通过 271 项后端自动化测试、前端类型/构建检查和三角色路由浏览器复核。测试范围与外部依赖边界见 `docs/测试说明书.md`。

## 6. 人工复核与责任

| 复核项 | 责任人工作 |
| --- | --- |
| 赛题符合性 | 逐项对照赛题原文和实际运行证据，不扩大宣传 |
| 教学准确性 | 教师审核 AI 生成资源、知识点关联和发布状态 |
| 代码质量 | 审查 diff、提交范围、边界条件和失败分支 |
| 安全与隐私 | 检查密钥管理、最小权限、敏感数据与日志脱敏 |
| 发布决策 | 只在全量门禁通过且外部配置齐备时建立竞赛发布包 |

AI Coding 提高了定位、实现和验证效率，但项目的产品选择、教学质量、安全责任和最终提交仍由参赛团队承担。
