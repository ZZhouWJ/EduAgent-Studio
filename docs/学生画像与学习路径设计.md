# EduAgent Studio 学生画像与学习路径设计

> 实施版本：V2.1
>
> 最近核对：2026-07-17

## 1. 设计目标

学生画像是课程内的个性化上下文，不是一份一次性问卷。系统通过对话确认、教师维护、测验反馈和学生自评持续更新画像，再将它用于：

- 学习诊断和多智能体资源生成。
- 课程知识点路径与当前学习点。
- 已审核资源的个性化筛选与推荐理由。
- Tutor 回答的难度、讲解方式和工具选择。
- 学生报告和教师学情分析。

画像以 `student_id + course_id` 唯一，同一名学生在不同课程中拥有独立画像和掌握度，避免跨学科混用。

## 2. 数据模型

### 2.1 `student_profiles`

| 字段 | 类型/范围 | 含义 |
| --- | --- | --- |
| `profile_id` | `INT UNSIGNED` | 画像主键 |
| `student_id` | `INT UNSIGNED` | 学生用户 ID |
| `course_id` | `INT UNSIGNED` | 画像所属课程 |
| `learning_goal` | `TEXT` | 学习目标 |
| `knowledge_base` | `TEXT` | 已有知识基础 |
| `current_level` | `TEXT` | 当前水平描述 |
| `cognitive_style` | `VARCHAR(100)` | 偏好的理解和学习方式 |
| `time_constraints` | `VARCHAR(255)` | 时段或其他学习时间限制 |
| `practice_level` | `VARCHAR(100)` | 实践能力描述 |
| `motivation` | `VARCHAR(255)` | 学习动机 |
| `error_prone_points` | `JSON` | 易错点列表 |
| `interests` | `VARCHAR(500)` | 兴趣方向，API 序列化为列表 |
| `resource_preferences` | `VARCHAR(500)` | 资源类型偏好，API 序列化为列表 |
| `weekly_hours` | `0`–`168` | 每周可用学习小时数 |
| `mastery_score` | `DECIMAL(5,3)` | 所有有效知识点掌握度平均值，0–1 |

唯一索引 `uk_student_course(student_id, course_id)` 保证课程内一名学生只有一份有效画像。记录使用 `is_deleted` 软删除。

### 2.2 `student_knowledge_mastery`

| 字段 | 类型/范围 | 含义 |
| --- | --- | --- |
| `mastery_id` | `INT UNSIGNED` | 掌握度主键 |
| `profile_id` | `INT UNSIGNED` | 归属画像 |
| `kp_id` | `INT UNSIGNED` | 课程知识点 |
| `mastery_level` | `DECIMAL(5,3)` | 掌握度，0–1 |
| `last_test_score` | `DECIMAL(5,3)` | 最近测验得分，0–1 |
| `last_test_date` | `DATE` | 最近测验日期 |
| `update_reason` | `VARCHAR(255)` | 更新来源摘要 |

`uk_profile_kp(profile_id, kp_id)` 保证每个画像对一个知识点只有一条当前掌握度。写入前会校验 `kp_id` 属于画像的 `course_id`。

### 2.3 对话与更新历史

| 表 | 作用 |
| --- | --- |
| `profile_dialog_messages` | 保存学生/助手消息、结构化抽取结果与是否已应用 |
| `profile_update_history` | 保存更新类型、更新前快照、更新后快照和摘要 |

不建立独立 `learning_paths` 表。学习路径从当前知识点层级和掌握度实时构建，因此反馈更新后下次查询会自动反映新状态，不需要同步一份容易过期的路径快照。

## 3. 12 维画像

| 维度 | 持久化/计算来源 | 应用 |
| --- | --- | --- |
| 学习目标 | `learning_goal` | 生成目标、规划优先级 |
| 知识基础 | `knowledge_base` | 决定讲解前置和背景密度 |
| 当前水平 | `current_level` | 难度和语言深度 |
| 认知/学习风格 | `cognitive_style` | 类比、图解、例题或结构化讲解 |
| 薄弱知识点 | `student_knowledge_mastery` 中 `< 0.5` | 路径当前节点和资源筛选 |
| 易错点 | `error_prone_points` | 错因分析和变式练习 |
| 兴趣方向 | `interests` | 案例背景与类比选择 |
| 资源偏好 | `resource_preferences` | 资源类型建议和推荐理由 |
| 每周时长 | `weekly_hours` | 学习量和节奏 |
| 时间约束 | `time_constraints` | 任务安排和计划建议 |
| 实践水平 | `practice_level` | 代码/实验任务难度 |
| 学习动机 | `motivation` | 反馈方式与目标提醒 |

`weak_points` 可以作为 LLM 对话抽取的候选文本向学生展示，但不直接覆盖掌握度表。权威薄弱点来自课程知识点与 `mastery_level`，避免将模型推断当成学习评测事实。

## 4. 对话式画像构建

### 4.1 抽取流程

```text
学生输入目标、基础、偏好或时间安排
  → 校验消息 1–4000 字符
  → 保存 student message
  → LLM Gateway 抽取结构化 JSON
  → 校验和归一化支持字段
  → 保存 assistant message + extracted_json
  → 返回 profile_patch 和 pending_changes
  → 学生确认
  → 事务内应用画像、写前后快照、标记消息已应用
```

抽取 Prompt 明确要求只填写学生描述中有依据的信息。LLM 调用失败或 JSON 无法解析时，系统返回空抽取结构，保留对话，但不编造字段值。

### 4.2 可应用字段

对话确认可以更新：

- `learning_goal`
- `knowledge_base`
- `current_level`
- `cognitive_style`
- `time_constraints`
- `practice_level`
- `motivation`
- `error_prone_points`
- `interests`
- `resource_preferences`
- `weekly_hours`

列表类字段在应用前删除空值和重复项；`weekly_hours` 截断到 0–168。同一条助手抽取消息只能应用一次，并发确认通过 `FOR UPDATE` 和 `is_applied` 防止重复写入。

### 4.3 权限

- 学生可读取自己的画像、对话与更新历史，并应用自己画像中的待确认抽取。
- 教师只能读写自己课程的学生画像。
- 管理员可执行平台级管理。
- 学生不能通过通用 `PUT /profiles/{profile_id}` 任意修改 `mastery_score`；学生画像更新使用对话确认和学习反馈链路。

## 5. 掌握度更新

### 5.1 教师/管理员更新

`POST /api/profiles/{profile_id}/mastery` 接收：

```json
{
  "kp_id": 58,
  "mastery": 0.72,
  "update_reason": "课堂测验与作业综合评估"
}
```

`mastery` 必须在 0–1，服务先校验知识点属于画像课程，再更新或插入掌握度。

### 5.2 学生学习反馈

学生可对已审核资源提交：

| `feedback_type` | 要求 | 掌握度行为 |
| --- | --- | --- |
| `quiz_result` | 必须包含 `quiz_score` 0–1 | 用得分更新资源首个目标知识点，同步最近测验 |
| `self_report` | 可包含 `self_mastery` 0–1 | 用自评更新资源首个目标知识点 |
| `study_note` | 可记录学习笔记 | 无数值时不修改掌握度 |
| `question` | 必须填写具体问题 | 记录疑问，无数值时不修改掌握度 |

更新后返回更新前/后掌握度、差值、最新画像、下一步资源和路径优先级建议。

### 5.3 综合掌握度

每次知识点更新后：

```text
student_profiles.mastery_score
  = AVG(该 profile 所有 is_deleted = 0 的 mastery_level)
```

系统不在当前代码中虚构“测验 70% + 自评 30%”之类未实施公式。测验和自评分别作为一次有明确来源的最新更新，`update_reason` 保留来源摘要。

## 6. 学习路径

### 6.1 输入

- 当前课程的所有有效 `knowledge_points`。
- `parent_kp_id` 表示的前置关系。
- 指定 `profile_id` 的当前 `mastery_level`。
- 无掌握度记录的知识点使用 0.5 作为中性展示值。

### 6.2 节点规则

| 条件 | 统计分类 | 界面状态 |
| --- | --- | --- |
| `mastery >= 0.7` | 已掌握 | 已掌握 |
| `0.4 <= mastery < 0.7` | 学习中；其中 `< 0.5` 计入薄弱数 | 学习中 |
| `mastery < 0.4` | 薄弱 | 薄弱 |

按知识点层级和 ID 顺序遍历时，第一个未掌握节点被标记为“当前学习点”。节点大小根据 `basic` / `intermediate` / `advanced` 难度调整，边由父知识点指向子知识点。

返回摘要包含：

- 知识点总数
- 已掌握数
- 薄弱数（`mastery < 0.5`）
- 平均掌握度
- `profile_id` 和 `course_id`

### 6.3 展示

学生端 `StudentLearningPath` 将 API 返回的 `nodes` 和 `edges` 渲染为交互式图谱，展示知识点、难度、掌握度、最近测验、预计时长和当前节点。图谱只展示后端已经进行所有权校验的课程/画像数据。

## 7. 画像驱动资源推荐

```text
读取画像资源偏好
  → 取 mastery < 0.5 的知识点
  → 若无薄弱点，取课程知识点并按掌握度升序
  → 查询 target_kp_ids 包含候选知识点的资源
  → 只保留 status = approved
  → 排除已提交反馈的资源
  → 根据最低掌握知识点与资源偏好生成推荐理由
```

当前资源查询使用 `FIND_IN_SET` 精确匹配逗号分隔的 `target_kp_ids`，避免知识点 `1` 误匹配 `10`。推荐资源按创建时间返回，资源偏好用于推荐理由，不应宣称已实现复杂机器学习排序。

## 8. Tutor 与多智能体使用画像

### 8.1 Tutor

Tutor 在每次对话前验证画像属于当前学生与课程，再将学习目标、水平、风格、偏好、时间约束和课程检索结果注入系统上下文。

### 8.2 教师资源生成

Diagnosis Agent 读取画像、知识点掌握度和学习历史；Planning Agent 根据诊断和目标安排学习路径；Resource Generation Agent 将画像中的学习目标和资源偏好与课程证据一起注入 Prompt。

画像是个性化上下文，不能绕过课程证据、内容安全或教师审核。

## 10. 数据隐私与安全

1. 画像、掌握度、对话和反馈都是课程内隐私数据，每个 API 在返回前检查所有权。
2. 教师不能通过更换 `profile_id`、`student_id` 或 `course_id` 访问其他课程。
3. 对话输入有长度上限，经 LLM Gateway 内容安全扫描，外部失败不返回内部异常。
4. 更新历史保存必要快照与摘要，密钥和凭证不进入画像或对话数据。
5. 测试使用临时用户和唯一标识，端到端验证完成后删除临时画像、掌握度和反馈。

## 11. 局限与后续扩展

| 当前边界 | 当前处理 | 扩展条件 |
| --- | --- | --- |
| 测验/自评作为最新值更新 | 保留测验日期与 `update_reason` | 有足够真实学习数据后再评估时间衰减或多证据融合模型 |
| 路径为实时规则图 | 规则可解释且立即反映掌握度 | 引入复杂路径优化前先建立教师评估指标和对照实验 |
| 资源偏好参与理由而非学习排序 | 候选已按薄弱点、审核和学习记录筛选 | 有足够点击/完成/效果数据后再评估排序模型 |
| 一个学生可有多课程画像 | `/profiles/me` 当前返回第一份有效画像 | 多课程实际使用增长时在学生端显式选择课程并按课程查询 |
