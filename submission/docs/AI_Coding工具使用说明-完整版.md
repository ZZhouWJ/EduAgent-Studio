## 3. 约束说明

### 3.1 禁止事项

1. **禁止直接提交**：不得将未经任何人工审核的 AI 生成代码作为最终实现提交。
2. **禁止直接用于生产**：AI 生成的关键业务逻辑（如认证、权限、支付相关）必须经过充分测试和人工复核。
3. **禁止泄漏敏感信息**：使用 AI 工具时不得输入真实的 API Key、数据库密码、用户隐私数据。
4. **禁止绕过测试**：不得用 AI 生成测试用例来规避实际测试。
5. **禁止直接复制生成代码**：AI 生成的代码必须经过理解、改写和验证，不得直接复制到项目中。

### 3.2 质量要求

- AI 生成的代码必须符合项目的代码规范（类型注解、命名约定、注释要求）
- 关键函数必须有明确的功能说明和参数注释
- AI 生成内容须标注来源（如"此函数由 AI 辅助生成，经人工验证"）
- 所有 AI 生成的代码必须经过以下验证之一：
  - 单元测试通过
  - 手动功能测试通过
  - 代码 Review 通过

## 4. 人工复核机制

### 4.1 代码复核流程

```
AI 生成代码
    ↓
开发人员初步 Review（语法检查、逻辑审查）
    ↓
单元测试 / 接口测试
    ↓
功能测试（手动）
    ↓
代码合并（需至少 1 人 Review 通过）
```

### 4.2 文档复核流程

```
AI 生成文档初稿
    ↓
团队成员交叉 Review（内容准确性）
    ↓
技术负责人审核（架构一致性）
    ↓
最终确认并发布
```

### 4.3 演示材料复核流程

```
AI 生成脚本/PPT 大纲
    ↓
团队试讲验证（话术流畅性、截图正确性）
    ↓
技术负责人审核（功能展示准确性）
    ↓
录制 / 现场演示
```

### 4.4 复核清单

**代码复核清单**：
- [ ] 代码符合项目编码规范
- [ ] 关键逻辑经过人工验证
- [ ] 单元测试覆盖核心功能
- [ ] 无安全漏洞（SQL 注入、XSS 等）
- [ ] 无硬编码敏感信息
- [ ] 类型注解完整
- [ ] 注释清晰准确

**文档复核清单**：
- [ ] 内容与实际系统一致
- [ ] 技术术语准确
- [ ] 示例代码可运行
- [ ] 截图与实际页面一致
- [ ] 无虚假或夸大描述

### 7.2 核心贡献声明

以下为本项目的核心技术贡献，均由团队成员自主完成：

1. **多智能体编排架构**：LangGraph StateGraph 的整体设计，5 个智能体的职责划分和协作流程
2. **证据优先生成链路**：BM25 检索 + 引用校验 + 可信度评分的完整防幻觉机制设计

5. **前端交互设计**：React 组件架构、ECharts 图谱集成、Tailwind 样式方案
