## 1. 测试目标

本说明书验证以下质量目标：

1. 学生、教师和管理员的核心业务流程可完整执行。
2. 多智能体生成、Tutor 辅导、课程知识库和学习效果闭环具有真实后端数据链路。
3. 资源生成的课程证据、引用、可信等级和教师审核可追溯。
4. 身份认证、角色权限、课程数据域和输入边界在异常情况下仍安全。
5. 前端在桌面与移动视口中无主要布局、运行时和可访问性错误。
6. 代码可以通过标准构建流程交付，数据库迁移可按顺序在新环境初始化。

## 5. 关键业务验收

### TC-E2E-001：学生 Tutor 答疑

**步骤**

1. 以学生角色登录。
2. 打开 AI 学习辅导，确认课程、画像与薄弱点上下文。
3. 输入「用银行转账案例解释原子性和隔离性的区别，然后给我 2 道判断题。」
4. 观察流式回答、课程引用、结构化判断题和推荐资源。
5. 对完成的回答提交“有用”反馈。

**预期结果**

- 接口流式完成，不出现空白等待。
- 回答与当前课程和学生水平匹配，只保留相关课程 chunk。
- 返回恰好 2 道判断题，题型和题量均符合请求。
- SSE 完成事件返回 `session_id`，会话与“有用”反馈均成功落库。
- 工具不可用时显式降级，不伪造多模态结果。

**实测结果**：通过。

### TC-E2E-002：教师多智能体资源生成

**步骤**

1. 以教师角色登录，打开多智能体工作台。
2. 选择课程、学生、知识点、资源类型和生成目标。
3. 启动生成，观察诊断、规划、生成、评测和审核建议进度。
4. 检查预览、质量分、修订次数和执行耗时。
5. 保存资源草稿。

**预期结果**

- 每个节点都推送状态，最终事件保留质量与审计元数据。
- 资源知识点引用属于请求课程。
- 草稿、证据链和操作审计在同一事务中保存。

**实测结果**：通过。开发模型的五阶段流程完成，质量分 8.5，草稿保存成功。

### TC-E2E-003：课程证据链

**步骤**

1. 执行 `32_seed_course_knowledge_base.sql`。
2. 检查课程材料、chunk 和已确认知识点关联数量。
3. 对「事务与 ACID」运行资源生成智能体。

**预期结果**

- 1 份已解析材料、9 个 chunk、9 个不同知识点和 9 条已确认关联。
- 生成内容包含整数 chunk 引用。
- 可信等级为 `high`，产生至少 1 条可持久化 evidence link。

**实测结果**：通过。

### TC-E2E-004：角色隔离和登录切换

**步骤**

1. 依次以教师、管理员和学生账号登录。
2. 快速切换账号并刷新页面。
3. 尝试用学生角色直接访问管理员路由。

**预期结果**

- 过期请求的 401 不得清除新账号 token。
- 刷新后会话恢复正确。
- 学生访问管理路由时被重定向到学生空间。

**实测结果**：通过。

### 7.2 安全边界

- 无效、过期或撤销会话返回 401。
- 连续失败登录按用户名和 IP 限流，429 含 `Retry-After`。
- 生产环境拒绝弱 JWT/API Key 密钥、通配 CORS、Mock Provider 和缺失模型凭证。
- 模型 API Key 使用 AES-GCM 加密，主密钥不足 32 字符时拒绝启动。
- 内容安全检查在 Provider 调用前阻止危险/越权请求，在 Provider 返回后屏蔽违规正文或工具参数。
- 错误响应和日志不返回密码、API Key、数据库驱动错误或调用栈。
