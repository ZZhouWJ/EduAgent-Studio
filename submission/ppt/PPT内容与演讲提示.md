## 统一视觉规则

- 画布：16:9，1920 x 1080。
- 主题：深炭黑、白、青绿色主色，珊瑚红只用于风险与人工审核节点。
- 字体：中文使用苹方/思源黑体，英文与数字使用 Aptos/Arial。
- 每页只保留一个主要结论，正文不超过 6 个信息单元。
- 架构和流程使用可编辑形状；产品能力页优先使用当前系统真实截图。
- 截图不得包含密码、API Key、`.env`、个人路径或无关测试数据。

## 第 1 页：封面

**标题**：智学工坊 EduAgent Studio

**副标题**：基于课程证据的个性化学习与多智能体资源平台

**页脚**：第十五届中国软件杯 A3 赛题 · V2.1 · 2026 年 7 月

**视觉**：深色底，右侧展示由“课程证据、学生状态、智能体、教师审核、学习反馈”组成的闭环轨道，不使用装饰性渐变。

**讲述**：我们不是做一个问答 Demo，而是把课程知识、学生画像、多智能体资源生产和学习结果放进同一条可追溯链路。

## 第 2 页：赛题要求转化为一个真实闭环

**核心结论**：A3 的必做项不是功能清单，而是一条必须持续运行的数据闭环。

**左侧问题**：

1. 通用生成不了解具体课程证据。
2. 静态画像不能反映学习变化。
3. AI 内容未经审核会直接放大错误。

**右侧验收链**：

```text
完整课程知识库
  -> 12 维画像与掌握度
  -> 五智能体资源生成
  -> 教师审核
  -> Tutor / 路径 / 任务 / 资源
  -> 反馈更新画像和推荐
```

**页底数据**：1 门完整课程 · 9 章证据材料 · 12 个画像维度 · 9 种工作台资源类型。

## 第 3 页：产品全景

**核心结论**：对话式主入口与专业功能页面并存。

**三角色轨道**：

- 学生：Tutor -> 画像 -> 路径 -> 任务 -> 资源 -> 反馈/报告。
- 教师：课程 -> 知识库 -> 智能体工作台 -> 审核 -> 学情分析。
- 管理员：用户/课程 -> 模型/Prompt -> 成本/安全 -> 审计日志。

**中央信息层**：MySQL 中的课程、知识点、画像、掌握度、资源、证据、审核和反馈。

**视觉**：三条角色轨道汇入同一个课程学习闭环，避免七宫格功能堆叠。

## 第 4 页：真实实施架构

**核心结论**：所有 AI 能力经过统一业务、安全和证据边界。

```text
React 18 SPA
  -> REST + SSE
FastAPI
  -> Auth / RBAC / Course Ownership
  -> Service / Repository / Transaction
  -> LangGraph + Tutor Supervisor
  -> LLM Gateway + Content Safety
  -> Course RAG + Evidence Validation
MySQL 8 | Redis 7 | SQLite Checkpoint | Persistent Files
```

**技术标签**：React 18、TypeScript、Vite 6、FastAPI、Pydantic 2、PyMySQL、LangGraph、Celery、Docker Compose。

**边界说明**：当前运行链路不依赖 PostgreSQL、pgvector 或 MinIO；课程检索使用 MySQL chunk、BM25 和中文 n-gram。

## 第 5 页：课程知识库与证据链

**核心结论**：生成结果能回到原始课程段落核对。

**流程**：

```text
材料上传与签名校验
  -> 解析和版本化分块
  -> 教师确认知识点关联
  -> BM25 + 中文 2-4 字 n-gram
  -> [引用:chunk_id]
  -> 课程/知识点/原文校验
  -> resource_evidence_links
```

**实测数据**：CS301 9 个章节、9 个不同知识点、9 条 confirmed 关联、9/9 主题可召回。

**真实截图**：`submission/assets/screenshots/teacher-knowledge-base.png`，展示“事务与 ACID”的检索命中与 chunk 原文。

**风险规则**：无有效引用时资源降级为草稿，不伪造高可信结论。

## 第 6 页：五智能体资源生产

**核心结论**：多智能体不是五个并排图标，而是有状态、可返工、可恢复的生产流程。

```text
Diagnosis -> Planning -> Generation + RAG
                         -> Assessment -> Teacher Review Suggestion
                              ^                 |
                              | score < 7       |
                              +---- Revision ---+   max 3
```

**运行特性**：SSE 节点进度、质量分、修订次数、SQLite checkpoint、草稿与证据同事务保存。

**真实截图**：`submission/assets/screenshots/teacher-agent-workbench.png`，展示节点轨迹、质量分和生成结果。

**人工边界**：Teacher Review Agent 只提供建议；资源只有教师通过后才进入学生端。

## 第 7 页：12 维画像与动态学习路径

**核心结论**：个性化来自可确认、可更新的学生状态，不是 Prompt 中的一句“请个性化”。

**画像流程**：自然语言 -> 结构化候选 -> 学生确认 -> 原子更新 -> 前后快照。

**路径计算**：知识层级 + 前置关系 + 掌握度 -> 节点顺序、预计时长、当前学习点和资源建议。

**画像维度示例**：知识基础、学习目标、认知风格、资源偏好、学习节奏、互动偏好、表达偏好、动机、可用时间、实践倾向等 12 个持久化维度。

**真实截图**：

- `submission/assets/screenshots/student-profile.png`
- `submission/assets/screenshots/student-learning-path.png`

## 第 8 页：Tutor 对话式主入口

**核心结论**：学生从问题出发，系统在后台完成画像注入、课程检索和工具协同。

**示例问题**：用银行转账案例解释原子性和隔离性的区别，再给我 2 道判断题。

**Supervisor 轨迹**：课程检索 -> 讲解 -> 练习 -> 回答汇总。

**输出**：流式 Markdown、课程引用、题目/代码/思维导图/PPT/图像/音频内容块、工具状态和建议问题。

**真实截图**：`submission/assets/screenshots/student-tutor.png`，展示引用与结构化题目卡片。

**降级规则**：Provider 不支持 tool calling 时使用注册表意图路由；外部能力未配置时明确提示，不伪造结果。

## 第 9 页：学习效果闭环

**核心结论**：一次学习行为会改变后续路径和推荐。

```text
教师任务 / 已审核资源 / Tutor
  -> 学生完成、测验、自评或反馈
  -> 更新目标知识点掌握度
  -> 重算综合状态与薄弱点
  -> 路径刷新
  -> 推荐重排
  -> 学生与教师分析更新
```

**业务约束**：每名学生的任务进度独立；学生资源接口只返回 `approved` 内容；学生不能更新他人任务或画像。

**真实截图**：`submission/assets/screenshots/student-feedback.png`，展示反馈记录和掌握度变化。

## 第 10 页：管理员治理与审计

**核心结论**：模型能力可配置、可限额、可追责。

**四个治理面**：

1. Provider、Model、Prompt 与加密凭证。
2. Token、耗时、成本与失败原因。
3. 输入、输出和工具参数内容安全。
4. 登录、操作、审核与策略变更日志。

**真实截图**：`submission/assets/screenshots/admin-governance.png`，展示调用审计与成本/安全指标。

**安全说明**：API Key 使用 AES-GCM 加密，页面和接口不回显明文。

## 第 12 页：差异化与交付边界

**标题**：让 AI 教学从“生成一次”变成“持续闭环”

**六项可验证差异**：

- 对话画像需要学生确认，并由学习行为持续更新。
- 课程 RAG 绑定真实 chunk 和教师确认知识点。
- 多智能体有状态、质量返工和重启恢复。
- 对话主入口与教师/管理员专业工作台并存。
- 资源发布保留教师最终决策权。
- 模型调用、内容安全、成本和操作统一审计。

**交付边界**：讯飞真实能力只在有效凭证联调通过后宣称；最终 MP4 需按当前脚本录制；Python CVE 扫描需在安装 `pip-audit` 的环境执行。

**收束语**：EduAgent Studio 将课程证据、学生状态、智能体协作、教师决策和学习结果连成一个可验证的高校学习系统。
