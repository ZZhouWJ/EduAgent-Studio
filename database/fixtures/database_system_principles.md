## 1. 数据库基本概念

数据库是按数据模型组织、长期存储并可被多个用户共享的数据集合。数据库管理系统（DBMS）负责数据定义、查询、更新、并发控制、完整性与故障恢复。数据库系统由数据库、DBMS、应用程序、用户和运行环境组成。

三级模式包含外模式、模式和内模式。外模式描述用户视图，模式描述全局逻辑结构，内模式描述物理存储。逻辑独立性和物理独立性使上层应用不必随底层结构的局部变化而改写。

## 2. 关系模型

关系可视为二维表，行称为元组，列称为属性，属性的取值范围称为域。候选键是能唯一识别元组的最小属性集，主键是选定的候选键，外键用于引用另一关系的主键。

关系完整性包括实体完整性、参照完整性和用户定义完整性。关系代数的基本运算包括选择、投影、并、差和笛卡尔积；连接和除法可由基本运算组合得到。

## 3. SQL 基本查询

SQL 查询的基本结构是 `SELECT ... FROM ... WHERE ...`。`WHERE` 在分组前过滤行，`GROUP BY` 建立分组，`HAVING` 在分组后过滤，`ORDER BY` 对最终结果排序。`COUNT`、`SUM`、`AVG`、`MAX` 和 `MIN` 是常用聚合函数。

SQL 中的空值使用三值逻辑，应用 `IS NULL` 或 `IS NOT NULL` 判断，不能用等号与空值比较。编写查询时应优先列出必要字段，避免无目的使用 `SELECT *`。

## 4. 多表连接与子查询

内连接只保留满足连接条件的行；左外连接保留左表全部行，右表无匹配时补空值；右外连接与之相反。忘记连接条件会产生笛卡尔积，是多表查询中常见且高成本的错误。

子查询可返回标量、一列或一张临时表。`EXISTS` 关心子查询是否返回行，关联子查询会引用外层查询当前行。在语义等价时，应结合执行计划比较连接和子查询，而不应凭固定规则选择。

## 5. 索引与查询优化

B+ 树索引适合等值、范围和排序查询。联合索引遵循最左前缀原则，索引列顺序应同查询中的高选择性条件、范围条件和排序需求联合设计。覆盖索引能在索引页中直接获得查询所需列，减少回表。

索引会占用存储并增加写入维护成本，不是越多越好。应使用 `EXPLAIN` 观察访问类型、扫描行数、选用索引和额外操作，再根据数据分布和实际负载优化。

## 6. 事务与 ACID

事务是不可分割的逻辑工作单元。原子性要求操作要么全部提交、要么全部回滚；一致性要求事务保持业务约束；隔离性要求并发事务不暴露不应见的中间状态；持久性要求已提交结果在故障后仍可恢复。

以银行转账为例，扣减 A 账户和增加 B 账户必须在同一事务中。执行前后总额不变体现一致性；任一步失败时两步都撤销体现原子性；其他事务不读到中间余额体现隔离性；提交后通过日志恢复体现持久性。

## 7. 并发控制与锁

并发执行可能造成脏读、不可重复读、幻读和丢失更新。SQL 标准定义读未提交、读已提交、可重复读和串行化四个隔离级别。隔离级别越高，异常越少，但并发度和吞吐量可能下降。

共享锁允许多个事务并发读，排他锁用于写入并阻止冲突访问。两阶段封锁保证冲突可串行化，但可能发生死锁。死锁应通过统一加锁顺序、缩短事务、死锁检测与超时回滚处理。MVCC 通过多版本降低读写冲突。

## 8. 范式与反范式

第一范式要求属性值不可再分；第二范式在第一范式基础上消除非主属性对候选键的部分依赖；第三范式进一步消除非主属性对候选键的传递依赖。BCNF 要求每一个非平凡函数依赖的决定因素都是超键。

分解时应兼顾无损连接和依赖保持。反范式是在明确性能瓶颈和一致性维护方案后，有意引入冗余以减少连接或计算成本；它不能代替正确的模型设计和查询优化。

## 9. 数据库设计 (E-R)

数据库设计依次经过需求分析、概念结构设计、逻辑结构设计、物理结构设计、实现和运行维护。E-R 模型用实体、属性和联系描述业务语义，联系基数包括一对一、一对多和多对多。

转换为关系模型时，实体集通常对应表；一对多联系通常在多端加入一端主键作为外键；多对多联系需建立中间表并保存两端外键和联系属性。完成设计后要用典型业务场景验证约束、查询和更新流程。
