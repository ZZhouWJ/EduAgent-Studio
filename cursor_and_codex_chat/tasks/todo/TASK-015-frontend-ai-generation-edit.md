# TASK-015 前端 AI 生成、输出编辑与批注交互页面

## 一、任务目标

完成前端 AI 生成、输出编辑与批注交互页面，对接 Stage-07 和 Stage-08 已实现的后端接口。

本阶段重点是在任务详情页中补充 AI 生成、输出版本编辑、另存为新版本、输出批注和批注状态更新能力。

## 二、允许实现范围

本阶段允许实现：

1. 任务详情页中的 AI 生成面板；
2. 模型选择；
3. 提示词版本选择；
4. 输入文本区域；
5. 调用 `POST /api/tasks/{task_id}/generate`；
6. 展示生成结果；
7. 输出版本编辑弹窗；
8. 乐观锁 `lock_version` 提交；
9. 另存为新版本；
10. 输出批注新增；
11. 输出批注列表；
12. 批注状态更新；
13. 与 Stage-07 / Stage-08 后端接口对接。

## 六、接口对接要求

### 1. AI 生成

应对接：

- `POST /api/tasks/{task_id}/generate`

请求体应包含后端要求的字段，例如：

- `branch_id`
- `model_ids`
- `prompt_version_id`
- `input_text`

要求：

- 模型列表应从后端模型接口读取；
- 提示词版本应从后端提示词版本接口读取；
- 调用成功后刷新输出版本列表；
- 单模型失败时应在界面中清晰提示，不应导致整个页面崩溃；
- 不得调用真实外部 AI API，前端只调用本项目后端接口。

### 2. 输出编辑

应对接：

- `PUT /api/outputs/{output_id}`

要求：

- 编辑弹窗必须携带当前 `lock_version`；
- 提交时必须传递 `lock_version`；
- 后端返回乐观锁冲突时，应向用户提示：
  `当前内容已被其他成员修改，请刷新后重新编辑，或另存为新版本。`
- 编辑成功后刷新输出详情和输出版本列表。

### 3. 另存为新版本

应对接：

- `POST /api/outputs/{output_id}/save-as-new-version`

要求：

- 新版本应以当前输出为父版本；
- 成功后刷新输出版本列表；
- 返回的新 `output_id` 和 `version_no` 应在界面中可见。

### 4. 输出批注

应对接：

- `POST /api/outputs/{output_id}/comments`
- `GET /api/outputs/{output_id}/comments`
- `PUT /api/comments/{comment_id}/status`

要求：

- `comment_type` 只能使用后端允许值：
  - `comment`
  - `suggestion`
  - `approval`
- 批注列表应展示批注人、类型、内容、状态和时间；
- 批注状态只能更新为：
  - `open`
  - `resolved`
  - `closed`
- 操作失败必须有清晰提示。

## 七、页面与交互要求

1. 保持 V3 Admin Vite 模板风格；
2. 复用当前项目的 Axios request 封装；
3. 复用当前登录状态和路由守卫；
4. 保持任务详情页已有基础信息、分支列表、输出版本列表和输出详情查看能力；
5. 新增交互应有 loading 状态；
6. 空数据应使用友好 Empty 状态；
7. 错误提示使用 `ElMessage` 或等价统一方式；
8. 不得展示后端异常堆栈；
9. 不得保存或展示任何 API Key、JWT Secret、数据库密码等敏感信息。
